**三个"四份 Demo 都没有"的关键增量**

1. **证据链面板** —— 用户看到的每一句话，都能展开成 **① 事实 → ② 模板 → ③ LLM 润色 → ④ 红线校验 → ⑤ 出口** 五段。
   这是"大量用 AI 但可控"唯一能被评委当场验证的形式。
2. **故障注入** —— 主动制造 ASR 低置信(0.41)、断网、短信网关异常、剂量模糊(0.5g/5g)、越界话术，
   演示**系统不会猜**（降级 / 求证 / 升级），而不是只演顺利路径。
3. **设备端逐屏信息架构**（11 节点 + 触摸控件）—— 与 `demo/device-prototype.html` 一致，是产品本体的完整形态。
   设备端、用户端、家属端共用同一个 `Episode` 实体，是"一内核三通道"的物理证据。

## 🎭 设备上的虚拟形象

**不是一个喇叭，是一个用户能认出来、看得见表情的「人」。**

**纯内联 SVG** 画出来的角色 —— 没有一张外部图片，离线可用，放大不糊。

### 五种表情，跟着发生的事自动变

| 状态 | 什么时候出现 | 画面表现 |
| --- | --- | --- |
| **待机** | 常态 | 轻轻呼吸 + 定时眨眼 |
| **说话** | 小暖播报时 | 嘴跟着动，配合逐字字幕 |
| **倾听** | 等用户回话时 | 眼睛睁大，眉毛抬起 |
| **关切** | 用户说"疼 / 晕 / 不舒服" | 眉毛皱起来 |
| **高兴** | "今天都办完了"的收尾 | 轻轻弹跳 |

技术上全部是 **CSS 动画 + 状态类**（`av-idle` / `av-speaking` / `av-listening` / `av-care` / `av-happy`）。接真实后端时，只要把情绪识别的结果映射到这几个类上。

### 设计取舍（答辩可以讲）

| 决定 | 为什么 |
| --- | --- |
| **不像机器人** | 没有金属、没有发光眼睛。机器感会让人更紧张 |
| **不像医生** | **不穿白大褂、不戴听诊器、不出现任何医疗器械** |
| **像讲解员** | 朴素的衬衫 + 一张工牌。是"陪您走完这段路的人"，不是"给您看病的人" |
| **年龄感三十来岁** | 比用户年轻一点，有精力照顾人；又不至于小到不放心 |

> ⚠️ **一条红线**：小暖**永远不穿白大褂、不拿听诊器**。形象上就必须让用户明白——**她负责陪您、帮您跑流程，但不负责看病。** 这和国标划的服务边界一致。

形象展示页深链：`v3.html#avatar`

## ⭐ v3.html 主流程

### 第一步：入口分流页

> **您好，我是小暖**
> 今天是谁来看病？点一下就行，选错了随时能重选。

| 选择 | 副标题 | 选中后进入 |
| --- | --- | --- |
| 👴 **老年人** | 记性不太好、一个人来，或者耳朵有点背 | 大字触屏 + 记忆辅助 |
| 👁️ **视力障碍** | 看不见或看不清。选这个，我全程用说的，不用看屏幕 | **直接进入语音通话** |
| 👂 **听力障碍** | 听不见或听得费劲。选这个，全程用字，我还能替您念给医生听 | 文字优先流程 |

- 老年人 / 听力障碍 → 各自的到院页，正常触屏
- **视力障碍 → 不出现任何需要点击的界面，直接开始全程语音讲解**

## 三类用户，三套交互契约

| 用户 | 称呼 | 交互被改成 |
| --- | --- | --- |
| **老年人** | 张奶奶 · 78 岁 | 记忆辅助：反复回答、复述校验、家属实时同步 |
| **视力障碍** | 王先生 · 56 岁 | **全程语音，零交互** |
| **听力障碍** | 李女士 · 34 岁 | **文字优先 + 替我说（文字转语音）** |

### 👁️ 视力障碍：全程语音，不用碰屏幕

> "**往前走十八步。好，停。**右手边是电梯按钮，我帮您按。"
> "出电梯，**往前走十二步，右手碰到门框就右转。**好，转过来，前面五步就是三百零二。"

- 不说"往左往右"，说**走多少步、摸到什么**
- 环境描述："正前方 3 米是护士站，扶手在您右手边"
- 东西都放**左手边**（右手拿盲杖），交还时说"现在放回您左手"
- **震动编码**：确认=短震两下 / 出错=长震一下 / 该走了=连续震三次
- 药盒贴**凸点**：早上圆点、中午三角、晚上方块

### 👂 听力障碍：文字优先 + 替我说

> ⚠️ **听力障碍用户下，小暖的旁白永不出声**（全部变成屏幕上的"小暖说·文字版"卡片），底部"和小暖通话"自动变成**"打字问小暖"**，语音开关变成**"替我说：开/关"**，只控制"念给医生听"那个功能。

**「替我说」= 文字转语音，放给医生听**（底部固定按钮）

- 打字 / 点常用短句 → 小暖**出声念给医生听**
- 明确写着："**这里的语音是放给医生听的，不是给您听的**"
- 短句一点就走：我有点疼 / 想休息一下 / 请再说一遍 / 请写给我看 / 我对青霉素过敏 / 我需要有人扶一下
- 「**全屏给医生看**」——把字放到最大转过去
- 给医生的卡片："我是听障人士。请对着手机说话，屏幕会显示文字。"
- 医生说话**实时转大字**；叫号用**震动 + 闪红光 + 大字弹窗**
- **每一屏都有「小暖说（文字版）」卡片**
- 药盒贴 **24pt 以上大字 + 红蓝绿三色**

### 🧠 老年人：记忆辅助

反复回答、复述校验、家属实时同步。

## 📱 家属端：一条会说话的微信

**家属端的核心矛盾只有一句话：人不在场。** 所以它不是一个 App，是一套通知机制。

- **主形态**：微信服务通知（被动推送）—— 家属什么都不用做
- **次形态**：微信小程序 / H5 链接（点开即看，零安装）
- **补充**：AI 电话外呼（只用于**需要签字**和**老人异常**两种情况）

**三层结构 80 / 15 / 5**：被动安心 80% · 主动查看 15% · 双向参与 5%

**只在 5 个节点推**：接到人 / 进关键检查 / 出结果 / 结束 / 异常

**三条隐私红线**：
1. **不做实时定位** —— 那是监控，不是陪伴
2. **不推医疗判断** —— 只说"医生说……"
3. **老人有权关掉** —— 任何时刻、任何一项

**关键差异化**：家属录 10 秒语音 → 小暖在合适时机（比如老人一个人等结果时）放给她听。

详见 `家属端方案.html`，可运行的家属端见 `v3.html` 顶部「家属端」。

## 💰 医保报销：用买菜算账的方式讲

标题就是结论：**「这 386 块，医保帮您出了 253 块」**

- **三宫格**：总共 386 / 医保出 253 / 自己掏 133
- **逐项拆解**，每项标 **甲类 / 乙类 / 丙类** 并说明原因
- **三个词大白话**：起付线＝门槛 / 报销比例 / 甲类全认·乙类先自付·丙类一分不报 / 封顶线
- **算给你看**：甲类 320 + 乙类扣自付后 41.4 = 361.4 × 70% = 253
- **想少花点**：教用户问医生"这个药有没有医保目录内的替代？"——但明确写"**我不替医生决定用药**"
- **要留的四张纸** + **免责**："最终以医院结算单为准，我不能替医保局给您打包票"

## 🎤 答辩演示建议顺序

1. **打开就是入口页** —— "这是放在医院大厅的公共设备，第一件事是问清你是谁"
2. **点「视力障碍」** —— 界面直接变成语音，一屏都不用点（**全场最有冲击力**）
3. **看「小暖形象」** —— 讲她为什么不像机器人、也不像医生
4. **点「听力障碍」→ 替我说** —— 打字，小暖出声念给医生听
5. **点「老年人」→ 复述校验** —— 闭环校验
6. **医保报销** —— 把最劝退的东西讲成人话
7. **家属端** —— 情感收尾

## 📌 三条硬约束（产品红线）

1. **永远说"医生说的是……"，永远不说"我认为……"**
2. **认不准就标出来问，绝不猜**（尤其剂量、手写字）
3. **重要医疗材料必须电子化留存，交接有留痕、可追溯**

形象上的红线：**小暖不穿白大褂、不拿听诊器、不出现医疗器械。**

依据：GB/T 47801—2026《社会化陪同就医服务 基本要求》（2026-11-01 实施）
