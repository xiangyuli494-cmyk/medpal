# 资产清点（S1）

## 何时用

用户给出一批待入库文件、一个目录，或问「这批资料里有什么」「把新文件登记进来」时。
不用于回答医学问题——那走 S3。

## 输入

- 文件路径列表（单个文件或目录下的全部支持格式）
- 可选的来源类型（公开标准 / 合成样本 / 内部资料）与登记人

## 步骤

1. 逐个文件调 ingest_asset，参数带上 title、source_type、ingested_by；目录则先列出支持的扩展名再逐个调。
2. 对每个返回，记录 asset_id、modality、锚点数量、识别到的实体。**锚点数为 0 视为失败**，写入告警。
3. 用 get_asset_card 按 modality 汇总一次，检查文本 / 表格 / 图文三类是否都非空；缺哪类就明确写出「本批缺 X 模态」。
4. 把「解析失败」「缺模态」「识别实体为空」三种情况单独列成告警表，不要混在台账里。
5. 输出台账（Markdown 表格）：asset_id、标题、模态、来源、锚点数、实体、知识库状态。

## 输出格式

    资产台账：共 N 份（文本 a / 表格 b / 图文 c）
    | asset_id | 标题 | 模态 | 锚点 | 实体 | 状态 |
    告警：
    - AST-... 解析失败：原因
    - 本批缺图文模态，R1 的多模态覆盖不足

## 禁止

- 不修改原始文件，只读
- 不对解析失败的文件编造内容补齐
- 不把「锚点数为 0」的资产算作入库成功
