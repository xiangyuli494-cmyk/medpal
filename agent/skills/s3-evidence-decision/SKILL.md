# 跨文档取证决策（S3）

## 何时用

用户给出主诉、症状描述、检验结果或病历片段，需要判断「该去哪个科」「要做什么检查」「现有用药有没有冲突」时。

## 检索-推理双驱动循环（最多 4 轮）

    1 检索：从当前实体集合出发 kg_query 取 2 跳路径，同时 search-knowledge-base 取段落
    2 判断：证据够不够？
        够      -> 进推理
        缺 X 类 -> 生成子查询回 1（把缺什么写进查询，例如「消化性溃疡 检查项目」）
        两轮无新增 -> 降级为「证据不足」，列出缺什么，不再硬答
    3 推理：只在已召回的证据上生成结论，每条结论必须挂 anchor_id
    4 冲突检测：同一结论存在反向证据 -> 标冲突、降置信度、把反向证据也列出来
    5 落链：trace_write 固化全过程

第 2 步是本技能的机制核心：检索不是一次性投喂，推理会反过来提出新的检索需求。

## 步骤

1. 从用户输入抽实体（症状 / 检验值 / 用药 / 疾病），不确定的先 std_align 归一。
2. 进入上述循环。kg_query 的 seeds 用归一后的实体，max_hops 默认 2。
3. 每条候选结论至少 2 条证据才允许输出；只有 1 条则标「低置信」。
4. 冲突必须显式呈现，例如「布洛芬与消化性溃疡存在禁忌关系」。
5. 调 trace_write 落链，输出报告路径。

## 输出格式

    结论：建议就诊 消化内科（置信度 0.74）
    建议检查：幽门螺杆菌呼气试验、胃镜
    证据：
      1. [AST-2026-000137#p3.t1.r2] 幽门螺杆菌检测 必查
      2. [AST-2026-000137#p5.s2] 胃镜检查适应症...
      3. [T-000912] 消化性溃疡 -requires_exam-> 幽门螺杆菌呼气试验
    冲突：布洛芬（NSAIDs）可致胃黏膜损伤，与本病存在禁忌关系
    缺口：无
    决策链：reports/TR-20261105-0007.md

## 禁止

- 不给药品剂量、不给处方
- 不下确定性诊断，措辞用「建议科室」「建议检查」
- 不引用没有 anchor_id 的证据
- 证据不足时不许猜，必须输出缺口清单
