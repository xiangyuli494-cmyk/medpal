## 0. 一句话结论

**限制清单有 12 条策略类，当前部署一条都没生效；另有 2 条配额类始终生效。**

因为 `NEXENT_SANDBOX_DEFAULT_LEVEL=local`，而 `backend/management/services/agent/management.py:1664-1666` 把整个策略短路掉了：

```python
level = NEXENT_SANDBOX_DEFAULT_LEVEL
if level == "local":
    return None
```

`SandboxConfig` 返回 `None`，于是内存上限、CPU 配额、30 秒超时、断网、shell 拦截、产物同步——一条都不作用于技能脚本。

所以方案 §3.3 那句「技能脚本跑在 Docker 沙箱里、能力受限」，在当前这套部署上**不成立**。要让它成立只差一个环境变量（§6），镜像已经拉好了（§2）。

## 3. 沙箱到底是怎么跑起来的

镜像的启动参数（§1 第 4 行）：

```
Entrypoint = []
Cmd        = jupyter kernelgateway --KernelGatewayApp.ip=0.0.0.0 --KernelGatewayApp.port=8888
             --KernelGatewayApp.allow_origin=* --ServerApp.allow_remote_access=True
             --JupyterWebsocketPersonality.list_kernels=True
User       = sandbox
WorkDir    = /home/sandbox/workdir
```

三个直接推论（**前两条只在 `level=docker` 时才成立，第三条是当前 `level=local` 的实际情形**——混着读会得出错误结论）：

1. **（仅 docker 级）「执行脚本」不是 `python xxx.py`**，而是往一个常驻 Jupyter kernel 里提交代码块。所以变量、import 过的模块在同一 kernel 生命周期内是保留的。
2. **（仅 docker 级）`scope=system` 时**容器进热池复用，冷却启动开销的同时也意味着**不同运行之间不保证干净**。
3. **（当前实际）但当前 `level=local`，这个容器一次都没起过**（`docker ps -a` 里没有 `nexent-sandbox*`）。技能代码实际是在 `nexent-runtime` 容器进程内跑的，既没有 kernel 隔离，也没有容器级资源限制。

第 3 点值得单独说：`nexent-runtime` 挂了宿主 docker socket（§1 第 6 行，`/var/run/docker.sock:ro`）。local 级下，技能脚本和 docker API 处在同一个容器里。

## 4. 限制清单

### 4.1 配置里写了 12 条，local 级下全部不生效

| 配置项 | 实测值 | 切到 docker 级后的含义 |
| --- | --- | --- |
| `NEXENT_SANDBOX_SHELL_POLICY` | `disabled` | 拦截 `subprocess` / `os.system`（`restricted`/`boxed` 才放行部分） |
| `NEXENT_SANDBOX_MEMORY_LIMIT_MB` | `2048` | 容器内存硬上限 2 GiB |
| `NEXENT_SANDBOX_CPU_QUOTA` | `1.0` | 1 核 |
| `NEXENT_SANDBOX_TIMEOUT_S` | `30` | 单步执行超时即杀 |
| `NEXENT_SANDBOX_NETWORK` | `disabled` | 沙箱内禁出网 |
| `NEXENT_SANDBOX_AUTO_SYNC_OUTPUTS` | `true` | 产物自动同步 |
| `NEXENT_SANDBOX_OUTPUT_BUCKET` | `nexent-artifacts` | 产物落 MinIO 的桶名 |
| `NEXENT_SANDBOX_DEFAULT_SCOPE` | `system` | 常驻热池，非每次新建 |
| `NEXENT_SANDBOX_DOCKER_IMAGE` | `.../nexent-sandbox:v2.7.0` | 容器镜像 |
| `NEXENT_SANDBOX_WORKSPACE_VOLUME` | `nexent-agent-workspace` | 工作区卷（已存在） |
| `NEXENT_SANDBOX_WORKSPACE_MODE` | `legacy` | 卷/绑定模式 |
| `NEXENT_SANDBOX_FAILURE_POLICY` | `local` | **docker 起不来时回退本地执行**——这条会稀释“隔离”的说法 |

这 12 条都经 `management.py:1666` 的 `return None` 被短路。

### 4.2 与隔离级别无关、始终生效的 2 条

| 配置项 | 实测值 | 说明 |
| --- | --- | --- |
| `MAX_SKILL_UPLOAD_SIZE_MB` | `10` | 技能包上传上限 |
| `MAX_SKILLS_PER_TENANT` | `1000` | 租户技能数上限 |

这两条在管理面（上传/发布接口）判定，不经过 `sandbox_policy`，所以 local 级也管得住。

### 4.3 沙箱镜像里有什么（切 docker 级后才用得上）

- Python **3.11.16**
- 有：`pandas` `numpy` `openpyxl` `docx`（python-docx）`Pillow` `lxml` `bs4` `matplotlib` `requests`
- **没有：`fitz`（PyMuPDF）**

## 5. 对方案的三条硬结论

1. **§3.3 第 143 行必须二选一**：要么切到 docker 级让那句话成立，要么把「跑在 Docker 沙箱里」改掉。现状是既没隔离、又声称有隔离，被评委点开控制台一问就露。
2. **有状态/重依赖的逻辑必须留在 MCP server**。方案 §3.2 的切分是对的，不用改——现在有了实证依据：脚本执行环境不可信、且随时可能被收紧。
3. **PDF 解析不能放技能脚本**。沙箱镜像没有 PyMuPDF，而 `agent/mcp-server/parsers.py:84` 的 `PdfParser`（第 92 行 `import fitz`）依赖 `fitz`。解析能力全部归 MCP server 侧（那边 venv 里装了）。
4. **`level=local` 下技能脚本与宿主 docker socket 同处一个容器**（§3 第 3 点，`/var/run/docker.sock:ro` 挂在 `nexent-runtime` 上）。答辩时若被问「技能脚本能不能碰到宿主机」，要给的是这个事实，而不是「跑在沙箱里所以隔离」。切到 docker 级后这条才消失。

---

## 6. 建议：切 docker 级，成本已经降到 4 步

1. 镜像已落盘：`nexent-sandbox:v2.7.0`，1.89 GB，digest 见 §2
2. 改 `deploy/env/.env` 的 `NEXENT_SANDBOX_DEFAULT_LEVEL=docker`
3. **重建**（不是重启）这两个容器：`docker compose -f E:\deepseek-data\nexent\deploy\docker\compose\docker-compose.yml up -d --force-recreate nexent-runtime nexent-config`
   —— 环境变量在容器创建时就固化了（`docker inspect nexent-runtime` 的 `Config.Env` 里已存着 `NEXENT_SANDBOX_DEFAULT_LEVEL=local`），`docker restart` **不会**重读 `.env`，照原命令做会以为改完了其实没改。
4. 触发一次技能调用，`docker ps` 应出现 `nexent-sandbox-*`；`docker inspect` 里应能看到 `Memory=2147483648`、`NanoCpus=1000000000`

风险与如实说明：

- 首次拉起会慢（热池建立后恢复）
- `FAILURE_POLICY=local` 意味着 docker 失败会静默回退本地执行。**答辩时不要把这条说成硬隔离**，要说“隔离级别 docker，失败回退 local，可通过 FAILURE_POLICY=error 关掉”。

**已补齐**：`agent/docs/assets/W0-01-console-version.png`（headless Edge 登录 `http://127.0.0.1:3000` 后截的全屏，右下角页脚为 `Nexent © 2026· v2.7.0`）。

取证方式：`playwright`（`channel="msedge"`，用本机已装 Edge，不下载浏览器）→ 打开首页 → 点「登录账户」→ 填 `suadmin@nexent.com` 与默认口令 → 截工作台页脚。脚本放 `medpal/tmp/`，不入库。

**一个必须记住的坑**：页脚版本号分两态。

| 状态 | 页脚显示 | 说明 |
| --- | --- | --- |
| 未登录（落地页） | `Nexent © 2026· v1.0.0` | 前端静态常量，**不是**平台版本 |
| 登录后（工作台） | `Nexent © 2026· v2.7.0` | 与镜像 tag 一致，才可作为版本依据 |

所以「打开控制台看一眼版本号」这件事，未登录状态下看到的是 `v1.0.0`，会把人带偏。要截图必须登录。

补充证据（不依赖截图）：§1 第 1 行的镜像 tag 与 §2 的 image digest——比截图更难伪造，也更容易复核。
