## 0. 一句话结论

**不是「只支持纯 Python」，而是两类判定并存：LLM 判定 + Code 判定。**
Code 判定才是被沙箱限死的那个，而它限得比「纯 Python」更狠——不能 `import`、不能 `open`、不能发网络请求、不能定义类、连模块级辅助函数都调不到。

所以方案 §4.2 那句「是否仅支持纯 Python 待 W0 核实」可以删掉，换成下面 §5 的结论措辞。

## 1. 官方文档证据

| 内容 | 链接 |

文档关键原文：

- 内置评估器共 11 个，其中 **10 个是 LLM 判定**，只有「格式规范性」是 **Code 判定**（内置实现检查 JSON）。
- 「一个评估任务最多选择 5 个已发布评估器」。
- 「**Code 判定**：填写纯 Python 评估函数，对格式、关键词、数值或其他确定性规则进行检查。」
- 「Code 评估器必须定义 `evaluate` 函数，并返回包含 `score` 和 `reason` 的对象」。
- 「代码会进行语法、安全和函数签名校验，并在运行时使用受限的内置函数集合。禁止导入未允许的模块、访问文件、执行系统命令、进行网络 I/O 或使用对象自省绕过沙箱。」

文档只说「受限」，没说限到什么程度。下面 §2 是源码级的精确边界。

| 位置 | 作用 |

| `backend/management/services/evaluation/common.py:18-52` `ALLOWED_BUILTINS` | 闸 3 的白名单，共 34 个名字 |
| `sdk/nexent/core/agents/sandbox.py:819` `_FORBIDDEN_SHELL_CALLS` | 闸 2 的 shell 调用黑名单 |
| `sdk/nexent/core/agents/sandbox.py:872` `_scan_shell_calls()` | 闸 2 的 AST 扫描实现 |

### 四道闸

| 闸 | 做法 | 失败表现 |
| --- | --- | --- |
| 1 语法 | `compile(code, "<evaluator>", "exec")` | `Code syntax error at line N: ...` |
| 2 AST 扫描 | `_scan_shell_calls(code) + _scan_evaluator_introspection(code)` | `forbidden operations detected: ...` |
| 3 白名单 exec | `exec(code, {"__builtins__": ALLOWED_BUILTINS, "json": json}, local_vars)` | `NameError` → `forbidden or undefined name` |
| 4 签名 | `inspect.signature` 必须有 `query / expected / actual / runtime_events`（或 `**kwargs`） | `missing required parameters: ...` |

### 闸 2 具体拦什么

- IPython 魔法：行首 `!`、`%system` / `%sx` / `%sc`、`%%bash` / `%%sh` / `%%script`
- `subprocess.run / call / check_call / check_output / Popen / getoutput / getstatusoutput`
- `os.system / popen / execv / execve / execvp / spawnl / spawnv / spawnlp / spawnvp`
- **任何以 `__` 开头的属性名或变量名**（`().__class__`、`__builtins__`、`__import__` 全部静态拒绝）

### 闸 3 白名单（34 个名字）

```
int float str bool list dict tuple set
abs round min max sum pow len range sorted reversed enumerate zip map filter any all isinstance
True False None
Exception ValueError TypeError KeyError IndexError AttributeError
```

外加 `json`（单独注入）。

**不在白名单里的常用东西**：`open`、`print`、`re`、`math`、`collections`、`datetime`、`functools`、`__import__`、`globals`、`locals`、`eval`、`exec`、`compile`、`getattr`、`setattr`、`hasattr`、`dir`、`type`、`id`、`repr`、`format`、`bytes`、`frozenset`、`divmod`、`hash`。

> 注意 `getattr` 和 `type` 都不在。想要鸭子类型必须用 `isinstance`，而 `isinstance` 的第二个参数只能传白名单里的类型。

### 运行时调用方式（决定参数名必须一字不差）

`scoring.py:637-647`：

```python
fn = local_vars.get("evaluate")
result = fn(query=query, expected=expected, actual=actual,
            runtime_events=runtime_events or [])
scores[name] = float(result.get("score", 0))
reasons[name] = str(result.get("reason", ""))
```

**全关键字传参**，所以形参名必须是 `query / expected / actual / runtime_events`。返回值只读 `score`（转 float）与 `reason`（转 str），**没有 `status` 字段**。任何异常 → 该评估器记 `0.0`，reason 写 `Code evaluator error: ...`。

### 产出物

| `agent/docs/W0-03-评估器限制核实.md` | 本文件 |

### 评估器判定什么

medpal（AI 辅助分诊与知识图谱智能体）的回答质量，三项加权：

| 项 | 权重 | 判据 |
| --- | --- | --- |
| 科室 | 0.50 | 回答里 `科室：X` 与参考答案的 `department` 比对（完全匹配 1.0，包含关系 0.5） |
| 检查项 | 0.30 | `检查项：A、B` 与 `exams` 做 Jaccard |
| 溯源完整率 | 0.20 | 回答里 `完整率：x` 必须 ≥ 参考答案的 `trace_completeness` |

`expected` 是评测集参考答案（JSON 字符串），`actual` 是智能体回答（markdown）：

```
科室：消化内科
检查项：胃镜、幽门螺杆菌检测
完整率：0.75
```

### 实测中挖出来的坑（文档里没有的）

**模块级辅助函数在 Code 评估器里是不可见的。** 官方用双字典 `exec`：

```python
exec(code, {"__builtins__": ALLOWED_BUILTINS, "json": json}, local_vars)
fn = local_vars["evaluate"]
```

模块级 `def helper()` 存进的是 `local_vars`，但 `evaluate` 的 `__globals__` 指向第一个字典。于是 `evaluate` 里调用 `helper` 必抛 `NameError`。

后果很脏：**四道闸全过、控制台能保存、能发布，一跑打分就全部记 0 分，reason 写 `Code evaluator error: name 'helper' is not defined`。** 不写日志根本发现不了。

唯一的写法：所有 helper 写成 `evaluate` 函数体内的内层 `def`（闭包），或者全部内联。本评估器选了前者。

这条已写进 `agent/eval/nexent_code_evaluator.py` 的 docstring 顶部，防止后来人再踩。

## 4. 直接推论（会影响别人的活）

### 4.1 平台评估器**算不出**溯源完整率

算完整率要查 `medpal.db`（`store.py:534` `1 - len(unresolved)/len(cited)`），Code 评估器没有 `open`、没有 `import`、没有网络，做不到。

**唯一出路**：由 `trace_write` 自己算好，把 `完整率：0.75` 当成一行文本写进智能体回答，评估器用字符串核对。评估器只能「验」，不能「算」。

### 4.2 50 条评测集的回答格式被反过来约束了

T5 写评测集时，每条用例的标准答案必须含这三个可解析字段，否则平台评估器一律 0 分：

```
科室：<科室名>
检查项：<检查项1>、<检查项2>
完整率：<0~1 的小数>
```

不允许的写法：`**科室**：消化内科`（因为白名单里没有 `re`，无法做通用的 markdown 清洗——当前实现只 `replace("**","")` 做了最小兜底）、把结论写成散文段落、把完整率只放进 `trace.json` 而不放进回答正文。

### 4.3 一个评测任务最多挂 5 个评估器

11 个内置里挑，或者自建。我们 50 条评测集建议挂：科室准确 + 检查项覆盖 + 格式规范性 + 1 条自定义 Code（就是本文件这条），留 1 个余量。

**控制台内实测尚未完成**，原因是 Nexent 未拉起：本机 `dockerd` 起不来（`error while opening volume store metadata database (/var/lib/docker/volumes/metadata.db): timeout`，BoltDB 1 秒 flock 超时，根因是 `/var/lib/docker` 跨 VHDX 挂载），归 T6 的 W1 任务。

1. 复刻是规则的照抄，不是官方代码本身；官方在闸 3 后还有一条 INFO 日志（不影响判定）。
2. 复刻省略了 `_scan_shell_calls` 的 pip install 豁免分支（评估器场景用不到）。
3. **无法验证 DB 落库、草稿/发布状态、评分范围校验（0~100 上限、`pass_threshold` 必须在区间内）** —— 这部分只能在控制台里验。
