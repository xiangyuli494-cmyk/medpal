# 访问控制与令牌（v0.1）

> 状态：W1 冻结。本文件等同 ADR-015 正文，编号在 W1 评审会补登到 11 号 ADR 索引。
> 解决的问题：三端共用一个后端，谁能看哪一条数据、凭什么看，现在没有写。W3 联调时这类问题会以最难看的姿态出现。

---

## 1 一句话方案

**身份分三类入口，数据可见性由 Consent 决定，服务端在 Repository 层强制过滤。**

认证解决「你是谁」，授权解决「你能看哪条」，两者都不在前端做。

---

## 2 三类入口的认证方式

| 入口 | 谁 | 认证方式 | 令牌有效期 | 存放位置 | 谁能撤销 |
| --- | --- | --- | --- | --- | --- |
| 设备端（kiosk） | 到院老人，自助使用 | **服务台登记：报姓名与年龄段，值班人员代为录入并绑定设备编号（ADR-019，无读卡器）**；服务台不在时可选 6 位绑定码 | 与 Episode 同生命周期，最长 4 小时 | 内存，不写 localStorage | 服务台、系统超时、用户按「归还」 |
| 家属端 H5 | 家属 | 一次性邀请链接（含短 token）或微信内免登录 token | 24 小时 | URL 一次性，兑换后转 HttpOnly Cookie | 用户本人（撤销 Consent） |
| 用户端 H5 | 会使用手机的当事人 | 手机号 + 短信验证码（演示环境固定 000000） | 7 天 | HttpOnly Cookie | 本人 |

**院内人员（`staff`）不持有本系统的任何前端会话。** 服务台对设备的介入只有两条：输入绑定码（一次性）与在工单系统侧接收升级通知。这两条都不需要登录本系统界面。

**设备绑定码的生成与校验**：

| 项 | 约定 |
| --- | --- |
| 生成方 | 院内服务台值班人员，对任意一个待开始的 `Episode` 生成 |
| 码型 | 6 位数字，`secrets.randbelow(1000000)` 补零 |
| 有效期 | 与 `Episode` 同生命周期，最长 4 小时；`Episode` 关闭即失效 |
| 使用次数 | **一次性**。设备校验成功后该码立即作废，重连凭 `session_id` 续传，不再用码 |
| 失败锁定 | 同一 `Episode` 连续 5 次校验失败，锁定 10 分钟，期间不可重新生成 |
| 存储 | 仅存哈希（`sha256(code + episode_id)`），服务端内存 + Redis，不落库、不进日志 |
| 校验时机 | 设备端 `POST /api/v1/device/bind`，请求体 `{episode_id, code}`，成功返回设备 token |

三条硬约束：

1. **令牌不进 URL**（一次性邀请链接除外，且兑换后立刻失效）；
2. **令牌不进日志**，日志里只记令牌前 6 位的哈希前缀；
3. **设备端令牌只对一个 Episode 有效**，设备换到别的单上必须重新绑定。

**自助优先原则**：绑定码是兜底路径，不是主路径。设备端的正常开机流程是「报到服务台登记（报姓名与年龄段）→ 值班人员录入并绑定设备编号」，全程不需要老人操作证件（ADR-019，无读卡器）。绑定码只在服务台不在场、或老人不想报姓名时使用。

## 3 授权：可见性由 Consent 决定，不由角色决定

角色只决定「能不能进这个入口」，具体某条数据能不能看，看 Consent。

| 资源 | 用户本人 | 家属（有授权） | 家属（已撤销） | 院方 |
| --- | --- | --- | --- | --- |
| Episode 基本信息 | 读写 | 只读 | 不可见 | 只读 |
| Timeline 时间轴 | 只读 | 只读（受 scope 限制） | **即时不可见** | 不可见 |
| Media 照片/单据 | 读写 | 只读（默认关闭，需单独授权） | 不可见 | 不可见 |
| Task 待办 | 只读 | 只读（仅进度） | 不可见 | 不可见 |
| AuditLog | 不可见 | 不可见 | 不可见 | 只读（本院区） |
| Memory 长期记忆 | 读写 | 不可见 | 不可见 | 不可见 |

**没有「材料交接签署」这一行。** 材料交接在设备端表现为 `PAY_AND_PICKUP` 节点的一次「已交付」确认，写一条 `Timeline`，不涉及任何签署方、签名或哈希存证。

「即时不可见」的判定：撤销写入后，下一次请求即不可见，**不做缓存宽限**。演示验收要求 5 秒内生效。

---

## 4 服务端强制点（三个，缺一不可）

1. **Repository 层强制过滤**：任何查询 Episode 及其子资源的方法，签名里必须带 episode_id 或 consent_scope，禁止「先查出全部再在视图里过滤」。
2. **视图层二次校验**：视图拿到对象后调一次 can_view(actor, resource)，返回 False 直接 403，并写一条 AuditLog。
3. **序列化层字段裁剪**：家属端用的序列化器与设备端不是同一个，家属端序列化器里根本没有「剂量」「诊断」这类字段，而不是取出来再隐藏。

第 3 条是防「前端藏起来但接口里有」这类事故的唯一可靠办法。

---

## 5 WebSocket 鉴权

- 握手时带令牌：Authorization: Bearer <token>。浏览器 WebSocket API 不能自定义头，降级方案是把 token 放进 Sec-WebSocket-Protocol，服务端在第一帧之前校验。
- 握手成功后，服务端把连接绑定到 episode_id，**连接级订阅只允许该单**。
- 收到跨单订阅：立即关闭连接（code 1008），记一条安全事件。
- 令牌过期后不主动断开，而是在下一次消息返回 AUTH_EXPIRED，由设备端换令牌重连。

## 6 错误码与用户可见文案

| 场景 | 返回 | 用户看到什么 |
| --- | --- | --- |
| 未带令牌 | 401 AUTH_REQUIRED | 设备端：「请到服务台让工作人员帮您开机」 |
| 令牌过期 | 401 AUTH_EXPIRED | 设备端静默续期；家属端：「链接已过期，请让家人重发」 |
| 越权访问 | 403 E_FORBIDDEN | 统一文案「没有查看权限」，**不说明为什么**（避免探测） |
| 授权已撤销 | 403 E_CONSENT_REVOKED | 家属端：「家人已关闭共享」 |
| 跨单订阅 | WS close 1008 | 设备端回到入口 |

任何一条错误都不得回显资源是否存在，403 与 404 对外表现一致。

## 7 验收用例（W3 联调时逐条跑）

| # | 场景 | 期望 |
| --- | --- | --- |
| 1 | 家属 A 用自己 token 请求家属 B 的 Episode | 403，且响应里没有 B 的任何字段 |
| 2 | 用户撤销授权后 5 秒内请求时间轴 | 403 E_CONSENT_REVOKED |
| 3 | 设备端 token 订阅另一个 Episode 的 WS | 连接被关（1008），无数据返回 |
| 4 | 过期 token 调用接口 | 401 AUTH_EXPIRED，无栈信息 |
| 5 | 绑定码连续 5 次输错 | 锁定 10 分钟，第 6 次即使输对也拒绝 |
| 6 | 家属端序列化输出 | 不含剂量、诊断、Memory 字段（字段级断言，不是「值是否为空」） |

第 6 条建议直接写成测试：拿家属端 token 请求，断言返回 JSON 的 key 集合等于白名单。

## 8 明确不做

- 不做 OAuth / SSO（八周内没有企业主体）；
- 不做多租户（单院区，一家医院一套部署）；
- 不做字段级权限配置界面（矩阵写死在代码里，改要改代码）；
- 不做生物识别与身份核验（R-2 不允许推断身份）。设备端**不设读卡器**（ADR-019），不采集、不存储、不显示证件号；建档只记姓名与年龄段，强身份核验由服务台在登记环节完成。
