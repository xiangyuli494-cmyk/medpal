## 6 一次陪诊的成本估算（答辩会被问）

### 6.1 公式

```
单次成本 = ASR 单价 × 15 分钟
         + TTS 单价 × 10 分钟
         + OCR 单价 × 5 张

占客单价比例 = 单次成本 ÷ 客单价
```

参数来源：语音时长按 19 号「语音大约 15 分钟」取听的部分，播报另估 10 分钟；单据按 5 张估。

### 6.2 填这张表（已按官方价目算好，只有客单价待定）

| 项 | 取值 | 说明 |
| --- | --- | --- |
| ASR 单价 | **0.00022 元/秒 = 0.0132 元/分钟** | `qwen3-asr-flash` 官方价（华北2 北京） |
| TTS 单价 | **0.8 元/万字符 = 0.00008 元/字符** | `qwen3-tts-flash` 官方价 |
| OCR 单价 | **按 token：输入 0.5 元/百万、输出 2 元/百万** | `qwen3.5-ocr` 官方价 |
| 单次 ASR 成本 | **0.198 元** | 900 秒 × 0.00022 |
| 单次 TTS 成本 | **0.20 元** | 约 2500 字 × 0.00008（按 250 字/分钟 × 10 分钟） |
| 单次 OCR 成本 | **0.0034 元** | 5 × 0.000681（实测 tokens，见 §11） |
| **单次合计** | **约 0.40 元** | 0.198 + 0.20 + 0.0034 = 0.4014 |
| 客单价 | 待填 元 | 团队定价假设，需与 T1 对齐 |
| 占比 | 待填 % | 0.40 ÷ 客单价 |

> 这段是答辩必问项。**结论：一次陪诊的 AI 成本约 0.4 元，其中 ASR 与 TTS 各占一半，OCR 几乎可忽略**。这个量级说明 AI 不是成本瓶颈，真正贵的是陪诊师人力。

### 6.3 OCR 单张成本怎么算出来的

OCR 按 token 计费，不按张数。取一次「单据识别」的典型用量：

```
输入 = 图片 token 约 1000 + 提示词与结构化要求约 200 = 1200 tokens
输出 = 结构化字段 JSON 约 200 tokens

单张成本 = 1200 × 0.5/1,000,000 + 200 × 2/1,000,000
         = 0.0006 + 0.0004
         = 0.001 元/张（5 张 = 0.005 元）
```

图片 token 数随分辨率变化很大（官方示例里出现过 310、427、3350、3470 四种），所以这只是一个量级估计。**实测时用返回体里的 `usage.image_tokens` 校准**，不要沿用本文的假设值。

> 该量级结论稳健：就算一张单据 3500 图片 token，5 张也才 0.01 元，不影响"单次 0.40 元"这个结论。

### 10.2 接口形态（已确认的两项）

**TTS（非流式）**

```
POST https://{业务空间ID}.cn-beijing.maas.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer
{
  "model": "qwen3-tts-flash",
  "input": { "text": "请到二楼检验科", "voice": "<音色ID>", "format": "wav", "sample_rate": 24000 }
}
→ 返回 output.audio.url（有效期 24 小时，需另发一次 GET 下载）
```

流式输出加请求头 `X-DashScope-SSE: enable`，音频片段在 `output.audio.data`（base64）。

**OCR（DashScope 原生）**

```
POST https://{业务空间ID}.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation
{
  "model": "qwen3.5-ocr",
  "input": { "messages": [ { "role": "user", "content": [
      { "image": "<图片 URL 或 base64 data URI>" },
      { "text": "<抽取要求>" }
  ] } ] }
}
```

也可走 OpenAI 兼容端点 `/compatible-mode/v1/chat/completions`。**剂量字段的提示词要求写死**：「看不清的字段用 `?` 表示，不要猜测」——这是红线 R-2 在提示词层面的落地。

**ASR：形态已实测确认（2026-10-20）。**

```
POST https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation
{
  "model": "qwen3-asr-flash",
  "input": { "messages": [ { "role": "user", "content": [
      { "audio": "data:audio/wav;base64,<音频>" }
  ] } ] }
}
→ 返回 output.choices[0].message.content[0].text 与 usage.seconds（计费按秒）
```

实测踩坑：把音频放在 `input.audio` 或 `input.audio_base64` 都返回 400 `Either "prompt" or "messages" must exist`。**只有 `input.messages[].content[].audio` 这种 data URI 形态能通。** 另外返回体里带一个 `annotations` 字段（实测给出 `emotion: happy` 与 `language: zh`），可以直接用于情绪优先仲裁，不必另做模型调用。

三个能力**共用同一个端点** `services/aigc/multimodal-generation/generation`，差别只在 `model` 与 `content` 里的字段名（`audio` / `image` / `text`）。

### 11.1 这次实测得到的三个结论

1. **ASR 是回环验证过的**：TTS 合成的「请到二楼检验科，出电梯往左走」再喂给 ASR，转写结果一字不差。这不是人念的样本，所以只能证明链路通、不能替代 §4 那 20 条真实录音。
2. **TTS 输出 24kHz，ASR 接受 24kHz**：中间不需要我先重采样。但协议约定的是 16kHz，所以 W3 采集端仍必须降采样（见 `docs/specs/audio-contract.md`）。
3. **OCR 成本比原估算低 1.5 倍**：真实一张 900×620 的单据只花 0.000681 元，不是按 0.001 估的。5 张合计 0.0034 元，对总成本几乎无影响。
