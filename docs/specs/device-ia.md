# 设备端逐屏信息架构 v0.2

> 状态：W1 交付物，T4 产出。冻结前置条件：与 `docs/api/ws-protocol.md` v0.1 的 `touch.event.target` 一致。
> 用途：设备端前端（`device/`）实现与评审的唯一界面依据。改这里等于改契约，须在 PR 里说明改了哪一行。
> 权威原型：`demo/device-prototype.html`（触摸屏形态、8 点位、11 场景话术）。原型没覆盖的节点在本文件里补齐，并在 §9 登记。
> 设备形态：**10.1 寸竖屏触摸屏（800×1280 物理像素，逻辑视口 480×800）、Chromium Kiosk、零打字、触摸 + 语音两种输入，无任何物理按键。**
> 关联：`docs/specs/domain-model.md` §2.1–§2.3（11 节点与 9 步换算）、`docs/api/ws-protocol.md` §3.2（触摸控件映射）、`docs/specs/access-control.md` §2（设备端认证）。

## 1 三条硬规则

1. **设备端不做业务判断。** 状态、话术、升级全部由服务端决定；设备端只渲染与采集（`docs/api/ws-protocol.md` §10 第 1 条）。本地能改的只有渲染参数：音量、语速、当前屏、陪伴开关。
2. **每个节点必须在屏幕主位置给出「下一步点哪里」的大字。** 任何一屏都不得只显示状态而不显示动作。
3. **不得弹出模态错误框，不得依赖手势。** 所有异常在同屏内降级（见 §5）；所有操作都能**单击完成**，不要求滑动、双击、双指。唯一的长按是「一键求助」，且失败时有单击兜底。

## 2 触摸控件体系

没有物理按键，所有操作都在屏幕上。控件分四类，位置固定，不随节点漂移。

### 2.1 常驻底栏（每屏都在，高度 120px）

| 位置 | 控件 | `target` | 尺寸 | 上行消息 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 左 1 | 🎤 按住说话 | `mic` | 200×104 | `audio.start` / `audio.end` | 按下发 start，松开发 end；按下即高亮 + 短震动 |
| 左 2 | ← 返回 | `back` | 96×104 | 无 | 本地退一屏，不退节点 |
| 左 3 | ☰ 主菜单 | `menu` | 96×104 | 无 | 本地换屏到主菜单 |
| 右 | 🔴 一键求助 | `sos` | 128×104 | `touch.event { target:"sos", action:"long_press" }` | 长按 1.5 秒触发；按住期间显示进度环；**单击后 3 秒内再单击一次也触发**（长按按不动的兜底） |

### 2.2 屏内主操作（每屏最多一个）

| 控件 | `target` | 尺寸 | 上行消息 | 说明 |
| --- | --- | --- | --- | --- |
| 主操作按钮 | `primary` | 通栏 ≥ 96px 高 | `touch.event { target:"primary", action:"tap" }` | 按钮文案由当前节点决定：我听明白了 / 确认挂号 / 对，记住了 / 我到了 / 去取药。**同时由服务端下发，设备端不自己编** |

服务端要二元确认时（`task.confirm` 请求），主操作按钮文案变成服务端给的问句的两个选项，点击发 `task.confirm { answer: "yes" | "no" }`。

### 2.3 屏内选项（0–5 个）

| 控件 | `target` | 尺寸 | 上行消息 |
| --- | --- | --- | --- |
| 选项胶囊 | `option:<slot_id>` | ≥ 88px 高，宽度按内容 | `touch.event { target:"option:<slot_id>", action:"tap" }` |

用于症状示例、科室列表、是的/没有/说不清。`slot_id` 由服务端在 `dialog.reply.slots` 里给出，设备端只回传，不解释含义。

### 2.4 设置面板（从顶栏 ⚙ 进入，本地生效）

音量、语速、方言、高对比（黄字/白字）、蓝牙助听器、陪伴开关。这些**纯本地**，不产生任何上行消息，也不改变 `EpisodeStatus`。设置面板里有一个「结束使用 · 清空缓存」按钮，走 §5 的 `wipe` 流程。

### 2.5 触摸目标规格（硬性）

| 项 | 要求 | 理由 |
| --- | --- | --- |
| 最小点击区 | **88×88 CSS px** | 老人手抖、指腹大；WCAG 2.5.5 AAA 要求 44px，本项目取两倍 |
| 控件间距 | ≥ 16px | 防误触相邻控件 |
| 正文最小字号 | 24px | 480 逻辑宽度下约一行 18 字 |
| 标题最小字号 | 19px | — |
| 按下反馈 | ≤ 100ms 视觉高亮 + 可选短震动 | 老人需要「我按到了」的确定性 |
| 触摸至页面反馈 | < 200ms（`docs/specs/nfr.md` 第 1 条） | 硬门槛，由 Playwright 记录 |
| 禁止的手势 | 滑动切页、双击、双指缩放、长按拖动 | 只保留单击与「按住说话」长按 |

**关于电源**：界面里没有开关键。设备由服务台开机并常驻运行；一次就诊结束时走「归还设备 · 清空缓存」，由设备自己回到待机屏。机身侧面有物理电源开关，属于维护用途，不进入交互设计，也不上协议。

## 3 屏幕骨架

每屏固定五个区域 + 一条底栏，顺序不变，位置不跳：

| 区域 | 元素 | 规格 |
| --- | --- | --- |
| 顶栏 | `.statusbar` | 高 48px：当前点位、陪伴开/关、🔒 本地加密、缓存项数、⚙ 设置入口（原型里这排落在设备外壳下方，真机在屏幕顶栏） |
| 标题 | `#scrTitle` `.s-title` | 19px 粗体，一行，不折行 |
| 正文 | `#scrBody` `.s-body` | 24px，行高 1.5，`role="status" aria-live="polite"` |
| 陪伴条 | `#scrComfort` `.s-comfort` | 16px，暖色底 `#3a2410`，默认隐藏，`.on` 才显示 |
| 选项 | `#scrOpts` `.s-opts` | 0–5 个胶囊，每个 ≥ 88px 高 |
| 主操作 | `#scrPrimary` `.s-primary` | 通栏按钮，≥ 96px 高，仅在当前节点有此动作时出现 |
| 字幕 | `#scrCap` `.s-cap` | 14px，与语音同步，`aria-live="polite"` |
| 底栏 | `.dock` | 高 120px，四个控件固定位置（§2.1） |

配色：屏幕底色 `#000`，正文 `--fg:#ffe600`（黄字）；`.white` 变体改白字高对比。正文不得小于 24px，标题不得小于 19px，字幕不得小于 14px。

屏幕纵向预算（逻辑 800px）：顶栏 48 + 标题 56 + 正文 260 + 陪伴条 56 + 选项 200 + 主操作 100 + 字幕 44 + 底栏 120 ≈ 784，留 16px 余量。选项多于 4 个时正文区自动收缩，**不允许滚动整屏**。

| 失败兜底 | 清空必须真的清空（`state.cache` / `state.user` / `state.record` / `state.reg` 全置空并重渲染），不得只改提示文案 |
| 原型 | ⚠️ 部分（`wipe` 已有，`home` 小结屏未做） |

## 5 三个跨节点屏

| 屏 | 触发 | 内容 |
| --- | --- | --- |
| `guide` 点位自动讲解 | beacon 触发（`setSpot`） | 「当前位置：<点位名>」「（beacon <B-0x> 已触发，自动播报）」「<讲解词>」。若当前在 `triage` / `nav` / `confirm` 屏，**只播报不换屏** —— 走到点位就把正在填的表单冲掉是原型里已经避开的坑 |
| `sos` 一键求助 | `sos` 长按 1.5 秒（或单击后 3 秒内再单击一次） | 「一键求助已发送」「已通知医院服务台」「位置：<点位>（beacon <B-0x>）」「时间：<HH:MM>」「请留在原地，工作人员正在赶来。」服务台确认派员后同屏追加「工作人员正在赶往<点位>」。**求助发送后底栏只剩「返回」可用**，防止误触 |
| `menu` 主菜单 | 底栏 `menu` | 六个大按钮（每行两个，各 200×120）：建档/登录、当前位置讲解、语音挂号、院内导航、我的医嘱、归还设备 |

### 5.1 降级链（任何屏都适用）

```
大模型生成 → 模板兜底 → 字幕（无声） → 大字只显示「下一步点哪个按钮」
```

任一级失败都不弹窗、不显示技术文案。用户能看到的只有 §8 那句「网络不太好，我再说一遍」。

## 6 从开机到归还的完整触摸序列

老人不用读任何说明，只点这几步走完主流程。括号内是等价语音。

| 步 | 动作 | 屏 | 说明 |
| --- | --- | --- | --- |
| 1 | 触摸屏幕任意位置（待机态唤醒） | `boot` | 开机自检，播报欢迎语 |
| 2 | 点选项 `idNew`（或说「建档」） | `login` → `userCard` | 身份证放读卡区建档；复诊点 `faceOk` 人脸调档 |
| 3 | 点主操作「我听明白了」 | `brief` | 听完今日行程，确认往下走 |
| 4 | 按住底栏 🎤 说「我胸闷」（或点症状胶囊） | `triageAsk` → `triageAskQ` → `triageResult` | 口述主诉 → 分诊追问 → 出科室建议 |
| 5 | 点主操作「确认挂号」 | `confirm` → `regOk` | 二次确认后挂号成功，拿到取号码 |
| 6 | 走到点位（beacon 自动触发） | `guide` | 到点自动讲解，不用点任何东西 |
| 7 | 按住 🎤 说「带我去心血管内科」（或点目的地） | `nav` | 五步导航，逐步播报 |
| 8 | 点选项「念医嘱」（或说「我的医嘱」） | `record` | 接诊完成后回放医嘱与复诊时间 |
| 9 | 紧急时长按右下 🔴（或点两次） | `sos` | 求助工单进服务台 |
| 10 | 点主操作「归还设备」 | `wipe` | 清空缓存、回到待机屏 |

**主流程只用两个控件**：底栏 🎤 与屏内主操作按钮。其余都是可选的分支。

## 9 未覆盖项与 T4 的补齐计划

原型 `demo/device-prototype.html` 覆盖 11 个节点中的 5 个（`ARRIVED` / `REGISTER` / `NAVIGATE` / `REPORT` 部分 / `HOME` 部分）。以下缺口由 T4 补齐：

| 缺口 | 归属周 | 验收 |
| --- | --- | --- |
| `brief` / `wait` / `inRoom` / `recap` / `plan` / `pay` 六屏 | W2 骨架、W3–W4 全通 | 每屏有标题、大字正文、明确的主操作按钮 |
| `recap` 的剂量不确定标注 | W4 | 置信度 < 0.8 时必须显式标出，且不得自动纠错 |
| `home` 小结屏 | W4 | 六项小结字段齐全 |
| 陪伴开关的状态栏指示 | W2 | 顶栏「陪伴 开/关」随开关即时更新 |
| 常驻底栏 `dock`（§2.1） | W1 骨架 | 四个控件位置固定、尺寸达标、`sos` 长按有进度环 |
| 设置面板 | W2 | 音量、语速、方言、高对比、助听器、陪伴开关六项本地生效 |
| `spots.ts` 内容抽离 | W2 | 8 条讲解词不在组件里硬编码 |
| 触摸目标尺寸审计 | W2 | Playwright 遍历所有可点元素，断言最小边 ≥ 88px |

### 9.1 与 v4 演示的对应

`demo/v4.html` 的设备端 28 屏是本文件的**内容来源之一**，但它的布局是演示用的三栏，不是 480×800 竖屏。移屏时保留文案、重排布局，不改话术。
