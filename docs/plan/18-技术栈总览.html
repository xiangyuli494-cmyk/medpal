单体部署，不分微服务。六人八周不具备拆分后的联调成本（ADR-009）。
技术版本包 / 组件用来做什么为什么选它ADR

Django5.xdjangoWeb 框架、ORM、后台既有排班 / 挂号 / 检查项数据资产可直接复用；重写为 FastAPI 在八周内没有回归窗口ADR-001

03前端技术栈

三个网页是三个独立工程，共用一套 API 契约与设计令牌，但不共用代码仓库目录。设备端是产品本体，用户端与家属端是它的两个远程延伸。

04AI 与语音技术栈

全部经适配器接口调用。业务代码里不允许出现供应商 SDK 的名字（ADR-010），这是能回退假实现的前提。
能力供应商 / 模型调用方式用在哪降级链
语音识别 ASRDashScope qwen3-asr-flashHTTP + 流式设备端语音输入、老人对话云 ASR → 浏览器原生 → 仅字幕
语音合成 TTSDashScope qwen3-tts-flashHTTP全通道朗读、视障导航播报云 TTS → 浏览器 speechSynthesis → 仅字幕
识单 OCRDashScope 多模态模型HTTP 图像输入检查单、处方单字段提取模型 → 正则兜底 → 低置信度当场追问
话术润色 LLMqwen 系列HTTP只做措辞润色，不做医学判断LLM 失败直接回退模板
知识图谱Neo4j（条件 C2）Bolt症状 → 科室映射，条件交付不启用时走规则表
三层话术管线（技术栈层面的硬约束）
  1. 模板层：固定文案，占位符填空，零 token 成本，覆盖全部主干场景
  2. LLM 润色层：可选，只改措辞不改事实
  3. 红线校验层：禁用词正则拦截，命中即回退模板层并记审计日志
全量台词交给 LLM 生成已被否决（ADR-012）：无法 100% 单元测试，禁用词无法规则化拦截，成本不可控。

08已否决的技术方案

答辩时最容易被问「为什么不用 X」，这张表就是答案。共 15 项，全部有 ADR 记录。
被否决的方案否决理由ADR
全部重写为 FastAPI既有排班、挂号、检查项数据资产无法复用；八周内无重写与回归窗口ADR-001
Django 与 FastAPI 混合两套框架并行维护，六人团队不具备对应维护与联调能力ADR-001
设备端原生 Android 应用须另维护一套代码；硬件更换时须重写ADR-002
设备端承载业务判断与端侧模型Zero 2W 算力不足；硬件到货前无法验证；智能分散后无法统一灰度与回滚ADR-003
用户端原生应用或纯小程序现有代码库即 uni-app Vue 3，迁移成本高于收益ADR-004
家属端独立 App功能仅为推送与时间轴，独立安装形态增加使用门槛ADR-005
WebRTC 音频通道实现与联调复杂度高于本期需求；首字延迟 1.5 秒内 WebSocket 已可满足ADR-006
生产环境用 SQLite与既有 MySQL 8 不一致，并发写入不可靠ADR-007
会话状态存数据库或 Celery会话须低延迟读写，不应依赖离线任务队列ADR-008
服务拆分微服务六人八周单次部署的规模撑不起拆分后的联调成本ADR-009
业务代码直接调供应商 SDK供应商不可替换；测试无法注入故障与降级场景ADR-010
向量库 / 知识图谱承载主链路Milvus、Neo4j、Chroma 均为容器依赖且未安装；陪诊主流程是结构化问题ADR-011
全量台词由 LLM 生成无法 100% 单测；禁用词无法规则化拦截；成本不可控ADR-012
演示版与正式系统分别实现集成阶段演示功能失效，返工成本高ADR-013
物理硬件承载主流程演示采购、镜像、音频通路与电源无法与软件主线并行；到货时间不受团队控制ADR-014

10版本与变更策略

锁定策略
  • 后端依赖写入 requirements.txt 并锁定次版本号
  • 前端依赖提交 package-lock.json
  • CI 只装锁定版本，禁止 latest
  • 依赖升级须单独 PR，不得混在功能 PR 里
选型变更流程
  • 以 ADR 草案提出，由 T1 组织全员评审
  • 有异议时异议方做不超过 2 小时的验证实验，以数据裁决
  • 已冻结选型的变更须同时评估接口契约、测试用例与排期影响
  • AI 供应商变更由 T5 提出，T6 依据评测数据判定
  • 跨周未闭环的变更按 W4 范围冻结机制转入条件交付清单
