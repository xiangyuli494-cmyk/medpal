## 第 1 章 总则

本章规定组织设计依据、时间模型、交付物编号、阶段口径与基线对齐项，作为后续各章的共同基准。

### 1.1 组织设计依据

项目组由 6 名在校学生组成，项目周期 8 周（W1 – W8），有效投入每人每周 4 – 8 小时，全周期 192 – 384 人时。组织设计遵循以下五项依据。

| 编号 | 依据 | 说明 |
| --- | --- | --- |
| ORG-1 | 单一责任人 | 每项交付物有且仅有一名责任人（Accountable）；责任人可分配工作，不得转移责任 |
| ORG-2 | 工作节奏隔离 | 领域逻辑（纯函数、可 100% 单元测试）与 AI 集成（外部依赖、供应商可替换）分设角色，避免外部能力变更波及领域层 |
| ORG-3 | 用户群体隔离 | 用户端面向记忆能力衰退的就医人群，工作台面向并行管理多名患者的陪诊师，两类产品不得由同一角色设计 |
| ORG-4 | 硬件独立性 | 硬件采购、烧录、结构、电源四项工作任一项延期均会占用两周以上工期，占 8 周工期的四分之一，不可承受；该四项自本版起整体归口 T2 并降级为条件交付 C3、C4，主演示载体改为平板或笔记本浏览器，仍不由其他角色兼任 |
| ORG-5 | 质量独立性 | 质量保证角色不承担业务功能开发；质量保证角色开始编写功能代码，测试独立性即失效 |

### 1.2 时间模型

全体成员为在校学生，课余时间不固定且各不相同。本项目**不设统一工作时段**：每人每周有效投入 4 – 8 小时，具体投入时段由各人自行安排；工时弹性，但交付节奏固定，以「周任务包」为管理单元。

| 项 | 规定 |
| --- | --- |
| 工时制 | 周任务包制。不设统一工作时段，不设按周期固定的集成时段与开发时段 |
| 项目周期 | 8 周（W1 – W8），自项目启动周起算 |
| 有效投入 | 每人每周 4 – 8 小时，投入时段由个人自行安排，不作加班假设 |
| 团队投入 | 6 人每周合计 24 – 48 人时；8 周合计 192 – 384 人时 |
| 排期最小单位 | 周；以周任务包为派发与验收单元，不得设置小于一周的任务项 |
| 任务包交付截止 | 每周日 24:00，须提交产出物与自测证据 |
| 固定会议 | 仅三类：周计划会、双周评审会、里程碑评审会（见第 6 章） |
| 里程碑周 | W2、W4、W6、W8 |
| 里程碑周缓冲 | 里程碑周不新增任务，预留当周工时的 50% 用于缺陷清扫 |
| 考试或课程冲突 | 本项目周期内不预设考试周。遇考试或课程冲突时，当周任务量按 50% – 70% 排，允许顺延一项任务；不得移动里程碑，不得降低 00-项目工期与范围基线 第 5 章的质量门槛 |

周任务包的四个节点（下达、自主执行、交付截止、交付确认）与四项要求见 6.2 节，其口径与 00-项目工期与范围基线 第 1.2 节一致。

排期原则：

| 编号 | 原则 |
| --- | --- |
| P-01 | 所有任务以周为最小排期单位，不设小于一周的任务项 |
| P-02 | 每项任务须在单个周任务包内可完成（预估工时不超过 8 小时），否则予以拆解 |
| P-03 | 每个周任务包须产出可演示的增量，不得连续两周无可演示成果 |
| P-04 | 里程碑周不新增任务，当周 50% 工时专用于缺陷清扫，不得安排新增功能 |
| P-05 | 临时考试或课程冲突导致的工作量缺口按周顺延，当周按 50% – 70% 排；顺延不得跨过里程碑周 |

| V-01 | T2 与 T5（共同持有） | 无障碍达标性与交互可用性。含在视障或听障模式下不可用的功能，以及目标用户无法完成的交互设计 | 出具书面结论，说明目标用户无法完成的理由 | 修改设计后由 T2 与 T5 复核通过 | 结论记入 docs/accessibility/ 走查报告或对应 Issue |
| V-02 | T4 | 工作台并发可用性。含导致陪诊师同时管理 3 名患者时出现混淆或误操作的设计 | 出具书面结论，说明并发场景下的失败路径 | 修改工作台信息架构或操作流后由 T4 复核通过 | 结论记入对应 Issue 或 ADR |
| V-03 | T6 | 质量门禁。含缺少测试的 PR，对全体成员生效，含 T1 | 依据 CI 结果或缺失测试的事实作出结论 | 补充测试后由 CI 复验通过；豁免须 T1 与 T3 同时同意并记录豁免理由 | 结论记入测试周报的打回 PR 与质量门禁判定两节 |

### 4.3 制衡原则

| 编号 | 原则 |
| --- | --- |

AI 代码审计检查表：

| 编号 | 检查项 | 判定标准 |
