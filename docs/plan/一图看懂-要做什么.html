二、三个「你以为要分开做、其实是一套」的地方

✕「设备端要做嵌入式系统 / 写 Linux 驱动 / 上 LVGL？」
不用。设备端就是一个全屏网页（Chromium kiosk 模式）。
平板开机 → 自动打开网页 → 全屏 → 就是"设备"。
树莓派只是换了个能装外壳的载体，跑的是同一个网页。
✕「用户端要发 App Store / 做原生 Android？」
不用。用 uni-app 写一份代码，编译成 H5 就能在手机浏览器打开。
原生打包、上架审核全部不做——8 周没有这个时间。
✕「还要做微信小程序？」
本期不做。小程序上架需要企业主体和审核周期，学生团队过不了。
家属端改用微信测试号 + H5 链接，演示时用 mock 推送面板。
基线里这是明确排除项。

四、明确不做的清单（把话说死，省掉纠结）

以下八项已从范围中排除，不要在讨论里反复出现：

  1. 微信小程序上架 —— 需企业主体与审核周期，改 H5 + 测试号
  2. 原生 App（Android / iOS） —— 用 H5 替代
  3. 嵌入式驱动 / LVGL 界面 / 自研 PCB —— 设备端是网页，硬件只做显示、触摸与震动
  4. 医院 HIS 系统对接 —— 本期不接，号源走自建号源中心
  5. 多医院覆盖 —— 只做一个场景做深
  6. 端侧大模型 —— 平板跑不动，全部走服务端 API
  7. 院内管理数据分析看板 —— 非核心链路，且与公益定位无关
  8. 院内人员（医生 / 护士）前端界面 —— 医院自有 HIS 承担
