## 1. 文档说明

## 3. 信息架构

### 3.1 三栏职责划分

| 区域 | 职责 | 禁止事项 |
| --- | --- | --- |
| 左侧控制台 | 仅修改状态对象，不执行渲染 | 不得直接操作文档对象模型 |
| 中部设备端 | 读取状态并渲染；负责采集与呈现 | 不得包含业务判断逻辑 |
| 右侧系统面板 | 展示系统内部处理过程 | 不参与业务流程，仅作观测 |

### 3.2 演示视角（通道）定义

| 视角 | 交互契约 | 页面数 | 关键验收要求 |
| --- | --- | --- | --- |
| 老年人通道 | 大字触控、记忆辅助、复述校验 | 11 | 字号可调；医嘱须具备原文卡片 |
| 视力障碍通道 | 全程语音，零点击 | 6 | 界面中不得存在必须点击的元素 |
| 听力障碍通道 | 文字优先、替我说 | 7 | 系统旁白出声次数为零；替我说输出面向医生 |
| 标准通道 | 标准流程、识单、医保 | 9 | 置信度三档可见；剂量字段禁止自动纠错 |
| 家属视角 | 微信推送、时间轴、隐私开关 | 4 | 不提供实时定位；授权可撤销 |
| 架构视角 | 分层、协议、测试资产 | 3 | 会话协议 v0.1 可见 |
| 故障视角 | 5 类故障注入 | 5 | 系统须降级、求证或升级，不得推断 |

### 3.3 陪诊状态机

主流程节点序列如下：

```
抵达确认 → 行程播报 → 取号挂号 → 候诊盯号 → 进诊室
        → 复述校验 → 检查规划 → 执行与导航
        → 缴费取药 → 看报告 → 小结回家
```

对外演示讲「9 步」，系统实现「11 节点」。9 与 11 的换算只在展示层做，不上协议：状态枚举、节点表与 11 → 9 映射表见 `docs/specs/domain-model.md` §2.1 – §2.3。协议侧 `flow.total` 固定为 11，对外步序由设备端换算（`docs/api/ws-protocol.md` §4.1）。

跨切面能力（各节点均须具备）：

| 能力 | 要求 |
| --- | --- |
| 记忆 | 进入节点时先查询长期记忆库 |
| 主动 | 静默超过 12 秒触发主动关怀；到点未执行触发提醒 |
| 兜底 | 任意节点可被「我不懂」「我找不到」「我要找人」打断，转入兜底子状态机，处理完毕后返回原节点 |
| 留痕 | 每次状态跃迁写入时间轴 |

## 4. 对话生成管线

面向用户的全部文本须经过以下三级管线，不得绕过。

```
结构化事实（fact）
   │
   ▼
① 模板渲染        约 90% 文本由此生成；确定性、可测试、可审计、无推理成本
   │
   ▼
② 个性化润色      可选；仅在允许的槽位内改写，不得新增医学事实
   │
   ▼
③ 红线校验        校验不通过时退回 ① 的输出
```

### 4.1 禁用词表

以下词语在任何面向用户的输出中不得出现：

```
没事的 / 不严重 / 不要紧 / 我认为 / 应该是 / 肯定是 / 你得的是
建议您吃 / 可以加量 / 加一片 / 不用去医院 / 小毛病 / 放心吧没事 / 我诊断
```

### 4.2 免责声明挂载规则

| 场景 | 须挂载的声明 |
| --- | --- |
| 涉及医学结论 | 以上是医生原话，我不能替医生判断。 |
| 涉及费用或医保 | 最终以医院结算单为准，我不能替医保局给您打包票。 |
| 涉及分诊建议 | 分诊仅作就诊参考，不能替代医生诊断。 |

### 4.3 LLM 使用边界

| 节点 | LLM 使用 | 依据 |
| --- | --- | --- |
| 入口播报、挂号二次确认 | 禁止 | 重要操作须使用固定脚本，防止确认语句遗漏 |
| 复述校验 | 禁止 | 复述内容须逐字取自医嘱，避免剂量被改写 |
| 剂量、药品名称 | 禁止 | 须原样转录，任何生成均视为缺陷 |
| 医保金额 | 禁止 | 涉及金额，须使用模板与明细拆解 |
| 行程播报、报告通俗化 | 允许（限槽位） | 仅作措辞包装，不得新增医学事实，改写后须通过事实一致性校验 |
| 分诊节点选择 | 允许 | LLM 仅负责文本到节点的映射，科室结论由确定性图遍历投票产生 |
| 识单结构化 | 允许 | 仅作转录，不得输出医学结论 |

## 5. AI 能力边界分级

| 分级 | 内容 |
| --- | --- |
| AI 主导 | 记忆持久化、留痕同步、闭环校验、检查排序求解、重复性情绪回应、信息结构化 |
| 人机协同 | 风险评估、选院选科建议、术语通俗化、动态重排、情感支持 |
| AI 禁入 | 医疗判断与建议、签字及法律行为、现场身体处置、与医护建立信任、复杂价值判断 |

AI 禁入区在演示版本中的对应实现：设备端在 `IN_ROOM` 与 `REPORT` 两个节点上只做「医生原话的复述与留存」，不做任何判断性表述；遇到医学问题一律播报「这个要问医生」并给出叫服务台或叫家属的入口。系统不代签、不做诊断、不给用药建议、不做现场身体处置。

## 6. 强制性约束

| 编号 | 约束 | 实现方式 |
| --- | --- | --- |
| R1 | 面向用户的医学相关文本须表述为医生原话来源，不得表述为系统判断 | 全部医学文本须取自证据字段 |
| R2 | 识别不确定时须标记并求证，不得推断 | 各字段附带置信度；低于 0.8 触发求证流程；剂量字段禁止自动纠错 |
| R3 | 重要医疗材料须电子化留存，交接有留痕、可追溯 | 材料以 `Media` 实体落库，交接在 `PAY_AND_PICKUP` 节点记一次「已交付」确认并写 `Timeline`；系统不做签署、不代签 |

形象约束：虚拟形象不得使用白大褂、听诊器及医疗器械元素。

## 7. 会话协议（演示侧呈现）

设备端与架构视角页面展示协议 v0.1。

**上行消息**

| 类型 | 结构 |
| --- | --- |
| 触摸事件 | `touch.event { target, action }`，target 取设备端触摸控件标识符之一，见 `docs/specs/device-ia.md` §2 |
| 音频分片 | `{ type, session, seq, payload }`，16kHz / 16bit / 单声道，每帧 200ms |
| 触控动作 | `{ type, session, action }` |

**下行消息**

`turn_result` 消息包含六个字段：

| 字段 | 内容 |
| --- | --- |
| caption | 字幕文本与重点标记 |
| speech | 音频地址、语速（0.86）、是否可打断 |
| device | 当前屏、分区状态与渲染延迟（~~震动编码~~ 已取消，ADR-019） |
| flow | 当前节点、序号、总数 |
| escalation | 升级级别：none、ask_again、call_staff、call_family、sos |
| confidence | ASR 与意图识别置信度 |

协议在第 3 周冻结后只允许追加版本号，不允许修改既有字段语义。

## 8. 无障碍契约

| 项目 | 要求 | 验证方式 |
| --- | --- | --- |
| 正文字号 | 不小于 18pt，推荐 20pt（老年人通道） | 三档缩放截图比对 |
| 按钮触控区 | 不小于 48dp | axe-core 检查与人工测量 |
| 对比度 | 正文不低于 4.5:1，大字不低于 3:1 | 高对比度模式切换前后截图 |
| 视力障碍通道 | 全程零点击可完成 | 端到端测试仅发送语音事件 |
| 听力障碍通道 | 系统旁白不出声 | 断言旁白路径语音调用次数为零 |
| 分区布局稳定 | 七个分区位置与高度占比不随屏变化，主操作始终占满屏宽 | 5 人盲测确认位置记忆生效 |
| 语音降级 | 无语音包时如实告知并转为字幕，不得弹出错误提示 | 注入语音接口不可用场景 |

## 9. 演示版本到正式系统的部件替换对照

| 演示版本实现 | 正式系统实现 | 替换时不得变更的部分 |
| --- | --- | --- |
| 模板与禁用词表 | 迁入 `domain/talk/`，配套不少于 200 条回归用例 | 禁用词表与免责声明规则 |
| 图谱查询（内置案例） | 成员 A 的知识图谱模块，封装于 `adapters/kg/` | 两级节点选择、图遍历投票、儿科过滤 |
| 规划打分函数 | 迁入 `domain/plan/`，接入医院实际约束数据 | 打分项与理由输出要求 |
| 浏览器语音合成 | 云端语音合成服务 | 降级链与失败处理规则 |
| 预置识单结果 | 多模态识别与版面分析，输出逐字段置信度 | 置信度三档策略与剂量禁止纠错 |
| 内存审计日志 | AuditLog 数据表 | 人工修正须保留原文 |
| 内存状态对象 | 服务端会话与 WebSocket | 设备端不得包含业务判断 |

## 10. 演示规程

### 10.1 演示脚本

演示顺序按「情绪影响、技术能力、产品思维、工程可控、情感收尾」编排，共 9 步，预计用时 8 分钟。

| 步骤 | 操作 | 说明要点 |
| --- | --- | --- |
| 1 | 停留在老年人通道抵达页面 | 说明该设备为医院大厅公共设备，首先确认使用者身份与当日事项 |
| 2 | 切换至视力障碍通道 | 说明同一会话状态仅更换渲染层，界面转为语音，全程无需点击 |
| 3 | 展开证据链面板 | 说明全部输出均可追溯生成过程，为可控使用 AI 的依据 |
| 4 | 切换至听力障碍通道并演示替我说 | 说明旁白不出声，语音输出面向医生 |
| 5 | 返回老年人通道，执行复述校验并确认 | 说明闭环校验以用户确认为完成条件 |
| 6 | 切换至架构视角，展示会话协议 | 说明协议冻结是并行开发的前提 |
| 7 | 切换至故障视角，依次注入 5 类故障 | 说明系统在异常场景下的降级、求证与升级行为 |
| 8 | 展示一键求助与服务台派员闭环 | 说明系统在紧急情况下的升级路径：设备发起 → 服务台接单 → 设备确认有人接手，链路必须闭合 |
| 9 | 切换至家属视角，演示语音留言 | 收尾说明 |

### 10.2 量化指标

演示须准备以下三项量化数据：

1. 老年人完成一次就诊的求助次数（启用与未启用系统对照）；
2. 走回头路距离（检查规划前后对照）；
3. 就诊前后焦虑自评得分（STAI-S 量表，10 题）。

### 10.3 异常处置预案

1. 演示设备准备两套（笔记本电脑与平板）；
2. 演示文件为零依赖单文件，可通过移动存储介质离线运行；
3. 语音合成不可用时切换至纯字幕模式，演示脚本不变。
