## 0 本周唯一的判断标准

动手之前先问一句：**我改的这一处，要不要通知另外五个人。**

要通知，说明它还是契约，先改文档；不需要通知，才轮得到写代码。

按这个标准，W1 能写的东西只有三类：文档、脚本、空壳。状态机实现、接口业务逻辑、UI 精修都是 W2 以后的事。看到有人在写这三类以外的代码，拉回来。

理由很直接：协议或模型一改，三端都要跟着改；现在改文档是一页纸，W4 再改是四个 PR 加一轮联调。八周工期没有这种余量。

## 4 按人拆解

### T1 · 项目经理 / 架构师 / 领域工程（8 小时）

#### W1-1.3 会话协议 v0.1 冻结（3h，P0）

现有 **docs/api/ws-protocol.md** 有 50 行草稿，上下行消息和 turn_result 结构已经写了。缺的是下面五处，补齐才算冻结：

1. **错误码表**，至少 6 个。每个写清三件事：谁触发、设备端怎么反应、要不要重试。没有这三句的错误码不算写完。
2. **降级链**，escalation 五个取值（none / ask_again / call_staff / call_family / sos）各自的触发条件写死成具体判断，例如「asr 置信度 < 0.6 连续两次」而不是「识别不准时」。
3. **断线续传**：seq 缺帧怎么补、重连后从哪个 turn 接、服务端保留多久（暂定 30 分钟）。
4. **心跳**：间隔、超时判定、超时后设备端显示哪句大字。
5. **mock 服务**：**tools/mock_ws.py**，30 行以内，收到 key 就回一条固定 turn_result，给 T6 写冒烟测试、T2 写重连用。

验收（三条全过）：

- 本地起 mock，用 websocat 连上并发一条 key 消息，收到 turn_result；
- 每个错误码在文档里都有「设备端行为」一栏，且是句子不是词；
- 降级链能用三句话讲清：什么情况重问、什么情况找服务台、什么情况叫家属。

证据：websocat 截图 + mock 启动命令 + PR。

### T5 · AI 集成与无障碍（6.5 小时）

#### W1-1.6 AI 选型对比 + 账号开通（4h，P0）

ASR、TTS、OCR 各选至少两家做对比，每家跑通一次最小调用。对比表列这几项：样本 20 条的准确率（自己听自己看）、单价、平均延迟、并发限制、是否需要实名或备案。单价只用于判断量级，不用于核算收费。

结论写 **docs/specs/ai-selection.md**，并给出调用量估算：一次陪诊大约几分钟语音、几张单据，折算成 token 与音频秒数，再乘院内日均单量。答辩时这个数字会被问。本项目为教学项目、不向患者收费，这一栏只用于说明技术选型的量级是否可行。

Key 存进 GitHub Secrets，不进仓库。截图只截变量名，不截值。

验收：对比表 + 三个能力各一张调用返回截图 + 调用量估算一段话。

#### W1-适配器接口草案（1.5h，P0）

**backend/adapters/base.py**：ASR、TTS、OCR、Push 四个 Protocol，加一组错误类型（超时、限流、内容为空、置信度过低）。**fakes.py** 里写骨架：FakeASR 返回固定文本，FakeOCR 返回固定单据字段。

验收：pytest 能 import；用 FakeASR 跑通「一段音频 → 一句话」；错误类型有对应的测试。

#### W1-无障碍 验收标准初稿（1h，P1）

## 8 周日怎么交

### 8.1 PR

标题按 12 号 §2.2 的格式，例如：

~~~text
docs(api): 冻结会话协议 v0.1 并补充错误码与降级链
feat(device): 增加设备端空壳与 kiosk 启动脚本
ci: 将 ruff 由软失败改为硬门槛
~~~

分支按 12 号 §2.1：docs/…、feat/F-…、fix/issue-…、test/T-…。一个 PR 只做一件事，别把「协议 + 术语表 + 模型」塞进一个 PR。

### 8.2 周报（三条，不超过十行）

~~~text
本周完成：<做了什么> —— 证据：<截图/命令输出/录屏链接>
没完成：<哪项> —— 原因：<一句话> —— 顺延到：<下周哪项>
下周需要谁：<人名 + 需要他给你什么>
~~~

证据不足的工作项按 13 号 §4.2 不计完成。这是纪律，不是针对谁。

### 8.3 周日验收会（30 分钟）

每人 2 分钟：交了什么、拿什么证明、下周卡在谁那里。T6 最后 5 分钟报 CI 与红线的状态。
