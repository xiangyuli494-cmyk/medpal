## 1. 总则

本章规定本文件的编制目的、依据文件、管理口径、使用规则与二十四周技术内容的压缩处置。

### 1.1 编制目的

1. 统一六个成员的技术口径。技术争议以本文件与架构决策记录为准；
2. 明确各技术层次的选定方案、落地周次、依据与责任人，避免重复讨论；
3. 冻结接口契约的最小可用字段集，作为三端在八周内并行开发、测试与验收的共同依据；
4. 记录架构决策在压缩工期下的影响与缓解动作，作为阶段评审与答辩阶段的技术依据。

### 1.3 管理口径

1. 时间口径：全体成员为在校学生，课余时间不固定且各不相同，故不设统一工作时段，采用周任务包制。任务于每周一 20:00 计划会下达，成员在周一至周日自主安排时段执行，每周日 24:00 前交付并附自测证据。有效投入按每人每周 4 – 8 小时核定，六人每周合计 24 – 48 人时。全部排期以周为最小单位，不设小于一周的任务项。见 00 号基线第 1 章。
2. 阶段口径：P0（W1）、P1（W2）、P2（W3 – W4）、P3（W5 – W6）、P4（W7 – W8），对应里程碑 M1 至 M4，与 00 号基线第 2 章及 14 号文件第 4 章一致。五个阶段压缩为五个单周或双周窗口，各阶段的验收标准不因窗口缩短而放宽。
3. 考试周口径：本项目八周周期内不预设考试周。如遇临时考试或课程冲突，当周工作量按 50% – 70% 排并允许顺延一项任务，不得压缩里程碑，见 00 号基线第 1 章。
4. 决策口径：本文件第 3 章的 ADR 是技术决策的唯一记录形式。口头结论与即时消息不构成决策。
5. 冻结口径：接口契约于 W1 形成、W2 确认冻结；冻结范围为第 4.3 节的最小可用字段集。冻结后仅允许追加次版本号，不得修改既有字段语义。
6. 硬件口径：平板或笔记本浏览器为主演示载体，物理硬件降级为条件交付项 C3 与 C4，见第 5.4 节与 ADR-014。设备端的技术形态、协议与验收标准不因载体变化而调整。

### 1.5 二十四周技术内容的压缩处置

八周工期下，二十四个月的技术安排不具备整体平移的条件。本节对原计划中的每一项技术内容给出处置，处置类型限于五类，处置依据见本节两表。压缩不得降低第 5 章质量门槛，亦不得删除第 3 章的既有 ADR。

#### 1.5.1 处置类型

| 处置 | 定义 | 判定依据 |
| --- | --- | --- |
| 保留 | 内容与周次口径基本不变，仅压缩单周工时 | 属必须交付 12 项，或属红线指标的验证手段 |
| 提前 | 原周次前移，内容不变 | 后置会使下游任务在 W8 前无验证窗口 |

### 2.3 选型变更控制

1. 选型变更须以 ADR 草案形式提出，由 T1 组织全员评审；

### 4.4 会话协议 v0.1

本节协议对应交付物 `docs/api/ws-protocol.md`，于 W1 形成 v0.1 并提供可收发的 mock 服务，W2 完成冻结评审。

#### 4.4.1 传输与编码

| 项 | 约定 |
| --- | --- |
| 传输 | WSS，端点 `/ws/session/{episode_id}`，端口 8000 |
| 消息编码 | 控制消息使用 JSON 文本帧；音频使用二进制帧 |
| 音频参数 | 采样率 16000 Hz，单声道，分片上传 |
| 会话保活 | 客户端发送 `ping`，服务端以 `pong` 响应；超时未获得响应即判定连接失效并触发重连 |
| 协议版本 | 由 `protocol_version` 字段标识，当前为 0.1 |
| 状态权威 | 状态机由服务端维护，客户端不得自行推进状态节点 |

#### 4.4.2 会话生命周期

| 阶段 | 触发 | 说明 |
| --- | --- | --- |
| 建立 | 客户端发送 `session.hello` | 服务端校验陪诊单与设备标识，返回 `session.ready` 并下发当前状态节点 |
| 交互 | `audio.start`、`audio.chunk`、`audio.end` 或 `text.input` | 服务端依次执行 ASR、状态机、话术管线与 TTS |
| 打断 | 客户端发送 `control.barge_in` | 服务端停止当前播报并进入新一轮识别 |
| 结束 | 客户端关闭连接或服务端判定超时 | 会话留痕写入 Timeline，AI 调用写入 AuditLog |
| 恢复 | 断线后客户端重新发送 `session.hello` | 服务端依据 `episode_id` 返回最新状态节点与未完成 Task |

#### 4.4.3 上行消息

| 消息类型 | 发送时机 | 字段 | 说明 |
| --- | --- | --- | --- |
| `session.hello` | 连接建立后 | protocol_version、device_id、episode_id、client、accessibility_mode | 会话初始化 |
| `audio.start` | 开始录音 | seq、sample_rate、encoding | 声明音频分片序列 |
| `audio.chunk` | 录音过程中 | 二进制帧 | 音频数据，服务端按 seq 重组 |
| `audio.end` | 结束录音 | seq | 触发 ASR 最终识别 |
| `text.input` | 文字输入 | text | 听障模式与兜底输入 |
| `control.barge_in` | 用户打断 | 无 | 停止当前播报 |
| `touch.event` | 触摸动作 | target、action | target 取设备端触摸控件标识符（`mic` / `back` / `menu` / `sos` / `primary` / `option:<slot_id>`），映射见 `docs/specs/device-ia.md` §2；action 取值为 tap / long_press；设备端是 7 寸 1024×600 横屏触摸屏，机身另有五个实体键（ADR-018） |
| `task.confirm` | 用户确认 | task_id、answer | 二元确认，用于低置信度信息 |
| `ping` | 保活 | 无 | 服务端以 `pong` 响应 |

#### 4.4.4 下行消息

| 消息类型 | 发送时机 | 字段 | 说明 |
| --- | --- | --- | --- |
| `session.ready` | 会话建立后 | session_id、episode_id、protocol_version、state | 返回当前状态节点 |
| `asr.partial` | 识别过程中 | text、confidence | 用于即时字幕 |
| `asr.final` | 识别完成 | text、confidence | 置信度低于阈值时进入求证流程 |
| `state.transition` | 状态节点跃迁 | from、to、at | 由服务端状态机产生 |
| `dialog.reply` | 话术生成完成 | text、template_id、slots、audio_available | 由三层话术管线产出 |
| `tts.audio` | 语音合成完成 | 二进制帧 | 承载 TTS 音频数据 |
| `caption.update` | 字幕更新 | text | 语音降级链的末端形态 |
| `guard.blocked` | 红线校验命中 | rule_id、action | action 取值为 replaced、escalated |
| `task.updated` | 任务状态变更 | task_id、state | 由状态机触发 |
| `escalation.notice` | 升级人工 | reason、target | 通知客户端已移交人工处理 |
| `error` | 发生错误 | code、message、retryable | 见第 4.4.5 节 |
| `pong` | 保活响应 | 无 | 响应 `ping` |

#### 4.4.5 错误码与降级

| 错误码 | 触发条件 | 客户端处理 | 是否可重试 |
| --- | --- | --- | --- |
| `ASR_TIMEOUT` | 语音识别超时 | 提示重说，保留已录分片 | 是 |
| `ASR_EMPTY` | 识别结果为空 | 进入求证流程，不中断会话 | 是 |
| `TTS_UNAVAILABLE` | 语音合成不可用 | 按语音降级链处理 | 是 |
| `GUARD_BLOCKED` | 话术命中红线规则 | 替换为合规表述或移交人工 | 否 |
| `STATE_CONFLICT` | 客户端状态与服务端不一致 | 以服务端状态为准并刷新界面 | 是 |
| `AUTH_EXPIRED` | 令牌失效 | 重新获取免登录 token | 是 |
| `RATE_LIMITED` | 请求超频 | 退避后重试 | 是 |

语音降级链：云 TTS → 浏览器 TTS → 仅字幕。任一级失败均不得弹出错误框，验证节点为 W5，见 14 号文件 W5 周任务与 15 号文件第 2.1 节质量目标。

#### 4.4.6 兼容规则

1. `protocol_version` 采用主次版本号。次版本号递增表示向后兼容的字段追加；
2. 不得修改既有字段语义，不得删除既有字段；
3. 破坏性变更须新增端点或递增主版本号，并同步更新 `docs/api/ws-protocol.md` 与 mock 服务；
4. 协议变更按第 4.6 节执行；W2 冻结后，破坏性变更一律不在本周期受理。

3. 默认值一经执行，即视为已决策事项，后续变更按第 2.3 节选型变更控制执行；
4. 默认值的取值理由宜在下一次风险登记表更新 R5 中书面说明，供里程碑验收与答辩引用。
