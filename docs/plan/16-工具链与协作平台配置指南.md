## 3. MCP 服务器选型

MCP（Model Context Protocol）服务器为 AI 编码助手提供外部工具能力。本项目按"是否解决当前痛点"筛选，不做全面铺开。

### 3.1 第一优先级（W1 即配置）

| 服务器 | 仓库 | 星标 | 解决的问题 | 使用者 |
| --- | --- | --- | --- | --- |
| **Playwright MCP** | `microsoft/playwright-mcp` | ★38.3k | 浏览器自动化、页面截图、表单交互。用于 E2E 调试与"设备端界面改完即截图确认" | T6、T2、T3 |
| **GitHub MCP** | `github/github-mcp-server` | ★33.7k | 直接读写 Issue / PR / 代码搜索，减少在 GitHub 网页与编辑器间切换 | 全员 |
| **Filesystem + Git + Fetch** | `modelcontextprotocol/servers` | ★91.3k | 官方参考实现：文件读写、git 历史查询、HTTP 抓取 | 全员 |

> **Playwright MCP 对本项目价值最高**：无障碍验收（axe-core）、设障注入后的界面断言、演示前界面回归，都可交由 AI 直接操作浏览器完成并截图留证。

### 3.2 第二优先级（W2–W3 配置）

| 服务器 | 仓库 | 星标 | 解决的问题 | 使用者 |
| --- | --- | --- | --- | --- |
| **Context7** | `upstash/context7` | ★63.2k | 拉取 Django 5 / Vue 3 / Playwright 的**最新**官方文档，减少 AI 使用过时 API（对应 AI 缺陷"接口幻觉"） | T1、T3 |
| **Chrome DevTools MCP** | `ChromeDevTools/chrome-devtools-mcp` | ★53.7k | 性能分析、网络请求检查、控制台错误定位。用于 P95 延迟与弱网降级调试 | T2、T5 |
| **Serena** | `oraios/serena` | ★30.3k | 语义级代码检索与符号级编辑，适合在 `domain/` 这类纯逻辑层做精准重构 | T1 |

### 3.3 条件使用

| 服务器 | 仓库 | 适用条件 |
| --- | --- | --- |
| **Figma-Context-MCP** | `GLips/Figma-Context-MCP` | 仅当 T3 使用 Figma 出设计稿时启用；否则跳过 |

### 3.4 裁剪原则

1. **每新增一个 MCP 服务器，须在 `docs/mcp.md` 登记**：用途、使用者、启停方式、安全提示；
2. 同一时刻每人启用的 MCP 服务器不超过 4 个，避免提示词膨胀与响应变慢；
3. **涉及医疗数据或 API Key 的路径不得开放给 MCP 服务器读写**；
4. MCP 服务器提供的能力不改变本项目的质量纪律：其产出仍须经测试与人工评审。

### 3.5 配置示例（VS Code / Cursor 通用 JSON 结构）

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "<在本地环境变量中配置，禁止写入仓库>" }
    },
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp"]
    }
  }
}
```

> 具体的包名与启动参数以各仓库 README 为准；上述写法仅示意结构。
> **令牌一律通过环境变量注入，禁止硬编码进配置文件并提交。**

## 5. 外部资源合规提示

1. GitHub Skills 与 MCP 服务器均为第三方开源项目，使用时须遵守各自许可协议；
2. 医疗场景数据不得上传至任何第三方 AI 服务，包括 MCP 工具链；
3. 星标数与更新时间来自 GitHub API 查询（2026-10-17），仅供选型参考，不代表质量背书；
4. 引入第三方工具须在合并请求中说明"为什么不用现有能力解决"，与依赖引入纪律一致（见 12 号文件）。
