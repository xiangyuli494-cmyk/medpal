## 1. 工时制与周任务包

全体成员为在校学生，课余时间不固定且各不相同，因此**不设统一工作时段**，只固定交付节奏。

| 项 | 规定 |
| --- | --- |
| 排期最小单位 | 周 |
| 工时投入 | 每人每周 4 – 8 小时，投入时段由个人自行安排 |
| 任务下达 | 每周一 20:00 线上周计划会（30 分钟），每人 1 – 3 项任务，含验收标准、预估工时、依赖方 |
| 交付截止 | **每周日 24:00**，须附自测证据（截图 / 测试输出 / 录屏） |
| 固定会议 | 仅三类：周计划会、双周评审会、里程碑评审会；其余沟通全部异步（GitHub + 项目群） |
| 总投入 | 8 周合计 192 – 384 人时，为原 24 周计划的三分之一，因此范围须按基线冻结 |

**周任务包四项要求**：单任务预估工时 ≤ 8 小时；每项须有明确验收标准；须标注依赖方；交付须附自测证据。

## 6. 项目管理纪律

### 6.1 五条开发纪律

1. 先编写规格说明，再编写测试，最后交由 AI 生成实现；缺少规格与测试的代码不得合并至 main 分支。
2. 单次 AI 生成任务规模不超过 300 行、不超过 1 个模块，超出须拆解。
3. AI 生成的代码须由另一名成员进行实质性修改后合并；无法修改视为未理解，予以退回。
4. T6 拥有合并否决权；缺少测试的合并请求一律退回，对项目经理同等适用。
5. 每名成员均为单点故障风险；W2、W5 各执行一次互备演练。

### 6.2 三条强制性约束

| 编号 | 约束 |
| --- | --- |
| R-1 | 医学相关表述须以医生原话为来源，不得表述为系统判断 |
| R-2 | 识别不确定时须标记并求证，不得推断，剂量字段尤须遵守 |
| R-3 | 重要医疗材料须电子化留存并完成交接双签 |

### 6.3 质量门槛（不因工期压缩而降低）

| 指标 | 阈值 |
| --- | --- |
| 禁用词出现次数 | = 0 |
| OCR 剂量字段错误数 | = 0 |
| 领域层单元测试覆盖率 | 100% |
| 测试用例总数 | W2 ≥ 40；W4 ≥ 120；W6 ≥ 180；W8 ≥ 240 |
| AI 评测集 | W6 ≥ 120；W8 ≥ 200 |
