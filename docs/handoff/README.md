# docs/handoff —— 模块交接单

**规矩：改了代码，就必须交一份自述，否则不能合进 main。**

CI 会查，不是靠自觉。

---

## 为什么要有这个目录

三个原因，都很实际：

1. **AI 写的代码要有人说清**。项目纪律第 3 条：AI 生成的代码须由另一名成员实质性修改后合并。改了什么，得写下来。
2. **数据流讲不清，说明没理解**。能画出输入到输出，才算真懂这段代码。
3. **答辩时有人问**。「这个模块你怎么做的」——翻出这份文档就能答。

---

## 怎么写

1. 生成：python tools/new_handoff.py --module 领域模型 --owner T1 --week 1
2. 填四处：一句话、数据流、我改了什么、怎么验证
3. 和代码放同一个 PR

文件名格式：W{周次}-T{工号}-{模块名}.md，例如 W2-T1-状态机骨架.md。

## 必须写的四节

| 小节 | 写什么 | 不合格的样子 |
| --- | --- | --- |
| 一句话说清它干什么 | 一句话，不超过 40 字 | 「完成了模块开发」 |
| 数据流 | 输入是什么、经过哪几步、输出是什么，配一张图 | 只贴一张架构图，没有本模块的输入输出 |
| 我改了什么 | AI 生成后你亲手改的地方，逐条列 | 写「无」，但代码明显是生成后没动过 |
| 怎么验证的 | 命令、测试名、截图或录屏 | 写「已测试」 |

## CI 怎么查

| 检查 | 规则 |
| --- | --- |
| 有没有交 | 本 PR 改了 backend/ frontend/ device/ tools/ 或 .py .vue .js .ts，就必须有 docs/handoff/ 下的新增或修改 |
| 小节全不全 | 四个小节缺一个就红 |
| 内容够不够 | 每节至少 20 字（去掉空格），写「完成了」不算 |
| 文件名对不对 | 必须是 W数字-T数字-名字.md |

本地先自查：python tools/check_handoff.py

## 别把它写成作文

两百字以内能说清就够了。写长了没人看，CI 也不加分。
