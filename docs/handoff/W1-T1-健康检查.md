## 一句话说清它干什么

给三个前端一个能请求的地址，证明「前端能连上后端」这件事成立了。

## 数据流

浏览器发 GET /api/v1/health → mock_api 用路径查 BODIES 字典 → 命中就返回 JSON 并加 CORS 头 → 前端拿到 ok 与 version 渲染到页面。

~~~mermaid
flowchart LR
  A[前端 5173] -->|GET /api/v1/health| B[mock_api :8000]
  B --> C{路径在 BODIES 里?}
  C -->|是| D[200 + JSON + CORS]
  C -->|否| E[404 空响应]
~~~

## 我改了什么（人工修改点）

1. 生成版本没有 CORS 头，三个前端跑在 5173 / 5174 / 5176，跨端口会被浏览器拦掉，补了 Access-Control-Allow-Origin。
2. 生成版本把路径判断写成 startswith，/api/v1/healthz 也会命中，改成精确匹配再去掉查询串。
3. 补了 404 分支，原来会抛异常把连接直接断掉。
4. 端口改成命令行参数，测试时不用改代码。

## 怎么验证的

| 验证方式 | 具体内容 |

| 手工验证 | curl http://127.0.0.1:8000/api/v1/health 返回 200 与 {"ok": true, "version": "w1"} |

| 跨端口 | 前端 5174 拉取成功，浏览器控制台无 CORS 报错 |
