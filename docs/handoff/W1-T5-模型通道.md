# 模块：模型通道（ASR/TTS/OCR/LLM）
## 一句话
一条命令打通 ASR/TTS/OCR/LLM 四项能力并打印耗时与估算成本，是 5.4 混合检索与 5.7 OCR 落地的共同前置。

## 数据流
本地样本文件 → probe_llm.py 读取并 base64 编码 → DashScope 四个接口（多模态生成 / 语音合成 / 兼容模式对话）→ 解析返回体取文本、音频 URL 与用量 → 控制台打印四行结果。

## 我改了什么（人工修改点）
- 初版 OCR 探针提示词太随意，模型返回版面坐标 JSON（rotate_rect）；改为显式要求「只输出 JSON、不要版面坐标」，并要求剂量数值与单位分开。
- 修正三处长行以满足 ruff E501，补 import re。
- TTS 成本按每万字符 0.8 元估算，非账单值。

## 怎么验证的
执行 `python agent/tools/probe_llm.py`，四项均 OK：ASR 565ms（识别「我挂的是内科。」）、TTS 632ms、OCR 1000ms（抽出 5mg）、LLM 461ms（回答「通道正常」）。`ruff check agent/tools/probe_llm.py` 通过。
