## 一句话说清它干什么

给设备端一个可在笔记本上运行的 7 寸 1024×600 横屏模拟器：屏内控件发 `touch.event` / `text.input`，WS 收 `turn_result`，并能嵌入用户端/家属端/工作台页面联调。

## 数据流

浏览器打开 `device/` → `session.hello` → mock 回 `session.ready` → 点击屏内控件发 `touch.event` 或输入文字发 `text.input` → mock/后端回 `turn_result` → 页面渲染字幕、主操作文案、节点与升级提示 → 回 `ack`；切到用户端/家属端/工作台标签时，iframe 加载对应地址，控件事件同时通过 postMessage 转发。

~~~mermaid
flowchart LR
  A[设备端屏内控件] --> B[session.hello / touch.event / text.input]
  B --> C[mock_ws 或后端]
  C --> D[session.ready / turn_result]
  D --> E[字幕 + primary_label + 节点 + escalation]
  E --> F[回 ack]
  A --> G[iframe postMessage]
  G --> H[用户端 / 家属端 / 工作台]
~~~

## 我改了什么（人工修改点）

1. 新建 `device/` Vite 工程，使用原生 JS，不引入 Vue/React，保持设备端轻量。
2. 按 ADR-019 改成 7 寸 1024×600 横屏、无实体按键；实现屏内 `primary` / `sos` / `spot` / `mic`（文字代替）与顶栏本地返回/菜单/设置。
3. 接入当前 WS 协议：连接后发 `session.hello`，控件发 `touch.event`，文字发 `text.input`，收到 `turn_result` 后渲染并回 `ack`，每 15 秒 `ping`。
4. 从 `turn_result.primary_label` 更新主操作按钮文案，从 `flow` 更新节点标题与步序，从 `escalation.level` 显示同屏大字，不弹错误框。
5. 增加“设备端/用户端/家属端/工作台”标签页，用 iframe 嵌入小组成员页面；从平板/Pi 访问时自动把 `127.0.0.1` 换成当前主机名，并把控件事件以 `{type:"medpal:control", target, action}` 转发给嵌入页面。
6. 增加调试工具条，把旧四键映射到当前协议：`GREEN_DOWN→primary`、`GREEN_UP→本地返回`、`RED_LONG→sos`、`SIDE→spot`。
7. 增加 `tools/start-kiosk.ps1`（Windows）与 `tools/start-kiosk.sh`（树莓派/Linux），自动追加 `?kiosk=1`，全屏无地址栏。
8. 给 `mock_api.py` / `mock_ws.py` 增加 `--host`，并在 `tools/dev.ps1` 增加 `-BindHost`，支持平板/Pi 通过局域网访问。
9. 增加/更新 `docs/specs/demo-carrier.md`：Pi 4B 4GB + 7 寸 1024×600 IPS 屏 BOM、端口、启动顺序、备份与降级方案。

## 已知风险与留待后续

- 用户端/家属端/工作台目前只有空目录，iframe 需要等对应开发服务器启动后才有内容；
- 跨域 iframe 可能被对方页面的 `X-Frame-Options`/CSP 拦截，已提供“新窗口打开”兜底；
- 麦克风/音箱尚未选型，`mic` 暂时只聚焦文字输入，不采集音频；
- 旧四键（GREEN_DOWN/GREEN_UP/RED_LONG/SIDE）只保留调试映射，不属于当前设备 IA；
- 树莓派 4B + 7 寸屏属于 C4 条件交付，不承担主流程演示（ADR-014）；
- `device/` 只做显示、发命令、渲染，不含业务判断。
