## 一句话说清它干什么

让做选型的人用同一把尺量出三家的「跑通没有、延迟多少」，而不是各拿各的截图比嘴上功夫。

## 数据流

命令行参数（能力 / 供应商 / URL / 模型 / 样本文件）→ 拼请求体（样本文件读成 base64 注入 `input`）→ Key 从环境变量取 → `urllib` 发一次 POST（网络错误重试一次，4xx/5xx 不重试）→ 计时 → 打印一行摘要 → 追加一条 JSONL 到 `tools/probe/results.jsonl`。`--dry-run` 在发请求前返回，不联网、不需要 Key。

~~~mermaid
flowchart LR
  A[命令行参数] --> B[build_payload]
  F[样本文件] -->|base64| B
  B --> C{--dry-run?}
  C -->|是| D[打印请求摘要并退出 0]
  C -->|否| E[读环境变量 Key]
  E -->|缺失| X[stderr 报错，退出 2]
  E -->|存在| G[urllib POST 带超时]
  G -->|网络错误| H[重试一次]
  G --> I[计时 + 取响应正文]
  H --> I
  I --> J[追加 results.jsonl]
  J --> K[退出 0 或 1]
~~~

## 我改了什么（人工修改点）

1. **只写一个文件，不拆成 19 号写的三个 `tools/probe/*.py`**：三种能力除了参数以外完全同构，拆三份等于把 HTTP、超时、计时、记账各抄三遍，正好踩中 14 号 AI 缺陷清单第 6 条「重复实现」。
2. **请求体不硬编码供应商字段名**：URL、模型名、额外 body 全部由命令行传入。理由是各家的字段名会变，写死在仓库里就等于把某天抄错的一版固化下来，还容易被误当成「已确认的接口」。
3. **重试策略与 `backend/adapters/legacy/client.py` 对齐**：只对网络错误重试一次，4xx/5xx 不重试——Key 错或模型名错，重发只会浪费时间且掩盖问题。
4. **加 `--dry-run`**：不需要 Key、不联网也能确认请求形态，无网环境与 CI 之外的自检都能用；这一点让我在没有真实 Key 的情况下也能验证脚本行为。
5. **结果写 JSONL 并加进 `.gitignore`**：测量记录要能累积看趋势，但不应反复污染 `git status`。
6. 顺带在 `.gitignore` 补了 `tools/probe/samples/`：录音与单据照片是合规红线里的原始素材，不能进仓库。
7. **AI 参与度：部分使用。** 初稿由 AI 生成；人工改动为上面 1–5 五处取舍，以及 `--dry-run` 分支的行为验证。按 14 号 §6.1 A4，合并前仍需另一名成员做至少一处实质性修改，候选见文末。

## 追加记录：实调后补的两处（2026-10-20）

拿到 Key 后真跑，发现两个必须修的地方，已一并改进并验证：

1. **`excerpt` 截断导致结果不可用**：原实现只把响应前 300 字符写进 `results.jsonl`，TTS 返回的音频 URL 恰好被截断，记录下来的响应无法再被程序解析。改为 `excerpt`（屏幕显示，300 字）+ `body`（下游解析，4000 字）两个字段并存。
2. **请求体形态原先靠命令行拼，实际拼不对**：三家实测后确认 DashScope 三个能力共用 `services/aigc/multimodal-generation/generation`，且 ASR/OCR 必须把文件放进 `input.messages[].content[].audio|image` 的 data URI 里（裸 base64 或 `input.audio` 都返回 400）。新增 `--preset dashscope`，把这些**实测确认**的形态固化，命令行只剩 `--capability` 与 `--file`。
3. 新增 `tools/probe/summary.py`：把 `results.jsonl` 聚合成对比表数字（只统计 200，失败请求不污染延迟均值），单价按返回体 `usage` 实算而非估算。

## 追加记录二：提示词外置（2026-10-20 晚）

新增 `--prompt-file`，把 OCR 提示词从命令行移到文件：

1. **为什么不用 `--text`**：提示词含换行、花括号与中文标点，塞进 PowerShell 参数会被吃掉引号（实测两次，`{"input":...}` 的引号直接被剥掉，JSON 解析失败）。改成读文件后，提示词可以放进版本库、可评审、可复用。
2. **提示词放 `docs/prompts/`**：按 14 号 §6.2 与 10 号 §541 指定的提示词库位置；`.txt` 是正文（单一来源、可直接喂给探针），`.md` 只写设计说明与判定口径，避免两处正文漂移。
3. **顺手修了 `summarize()` 的递归缺陷**：它只递归 dict 不递归 list，导致 dry-run 把整张图片的 base64 全打印出来（一次刷屏十几 MB）。现在 list 也会被遍历压缩，同一条命令的请求摘要从几 MB 降到 147 字符。

验证：`ruff check .` 通过；`--dry-run` 输出 `请求体长度 147 字符；含「已省略」= True`；退出码 0。

## 追加记录三：OCR 输出校验器（2026-10-22）

新增 `tools/probe/validate.py`，把「模型说出的话」与「我们允许它说的话」分开：每次 OCR 输出先过校验，再决定是否落库。

1. **为什么需要**：实测逼出来——提示词字段白名单不生效（输出「血型/兵役状况/宗教」等户籍字段）；一次全表抽取把金额当剂量（`08_取药单` 抽出 `剂量: 14.54元`）；长单据输出被截断导致 JSON 解析失败；模型会照抄提示词示例里的「医生/时间」。
2. **两级判定**：致命（禁用字段、剂量含「元/￥」、剂量缺单位、JSON 不完整）→ 不得落库；警告（doc_type 不在枚举、字段不在白名单、`?` 未登记）→ 记录并人工介入。
3. **故意不让警告升级为致命**：`doc_type` 写成「江苏省医疗住院收费票据」属措辞差异，一刀切会让评测失真。
4. **自测内置**（`--selftest`，7 用例，不联网）：正常处方、户籍字段混入、金额误当剂量、剂量缺单位、类型不在枚举、问号未登记、截断 JSON。
5. **定位**：W1 放 `tools/probe/`（本周只允许交脚本），W5 迁入 `backend/adapters/ocr/` 成为适配器契约的一部分。

验证：`python tools/probe/validate.py --selftest` → 7/7 通过；`ruff check .` 全仓通过（首轮 2 处 E501 已修）。

## 追加记录四：逐字段抽取 + 值有效性校验（2026-10-22）

新增 `tools/probe/fieldwise.py`，把「一次问全表」改成「一次问一个字段」。

1. **动机**：一次全表抽取实测 12 张里 4 张 JSON 被截断、2 张类型误判、1 张金额当剂量。单字段问答输出极短，**结构上不可能截断**。
2. **实测结果（10 类单据、27 个字段）**：可用 10（37%）/ 空 13 / 垃圾 4 / **致命 0**。致命从 2 降到 0，但可用率暴露了新问题。
3. **新暴露的三类垃圾值**（这是本次真正产出）：把表头当值（`项目 → "项目"`）、把区块名当值（`药品名称 → "门诊药房取药"`）、纯单位碎片（`自付 → "元"`）。已加入 `judge()` 硬规则拦截，并计入「垃圾」独立统计而不是混进可用率。
4. **模型会无视「只输出值本身」**：仍然返回 `{"剂量": ""}` 这种 JSON（第三次复现同类行为），因此解析层必须兼容两种形态，不能假设提示词被遵守。
5. **结论（要写进 W5 契约）**：三层缺一不可——逐字段抽取防截断、值有效性校验防垃圾、人工校对保剂量红线。**37% 这个数字不能直接进选型表**，因为它只是"抽到且不像垃圾"，尚未与原文比对。

验证：`ruff check .` 通过；`fieldwise.py` 全量跑通，输出「可用 10 / 空 13 / 垃圾 4 / 致命 0」。
