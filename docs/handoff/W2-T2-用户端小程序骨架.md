## 一句话说清它干什么

让用户端用一套 uni-app 代码同时编译出 H5 与微信小程序，先把四个页面的壳跑起来。

## 数据流

页面只调用 pinia store → store 调 `services/protocol.js` 构造上行消息 → `services/transport.js` 决定走演示脚本还是 `uni.connectSocket` → 下行消息回到 store 归一化 → 页面重新渲染。演示模式不连后端、不连数据库。

~~~mermaid
flowchart LR
  A[页面 home/session/journey/profile] --> B[stores/session.js]
  B --> C[services/protocol.js]
  C --> D[services/transport.js]
  D -->|DEMO_MODE=1| E[mock/session.js 11 节点脚本]
  D -->|DEMO_MODE=0| F[ws://.../ws/session/episode_id]
  E --> G[下行 turn_result]
  F --> G
  G --> C --> B --> A
~~~

## 我改了什么（人工修改点）

1. 新建 `frontend/user-app/` uni-app 工程，固定 `@dcloudio/*` 版本为 `3.0.0-5030320261023001`、Vite `5.2.8`，避免 `latest` 标签指向 Vue 2 版本。
2. 修 `vite.config.js` 的插件导入：本包是 `"type": "module"`，插件的 CJS 默认导出多包一层，直接 `uni()` 会报 `uni is not a function`，改为取 `.default` 兜底。
3. 把协议拆成纯函数层 `protocol.js` 与平台层 `transport.js`，让 39 条测试用 `node --test` 跑，CI 不需要安装 533 个 npm 包。
4. 11 节点 → 9 步换算写在 `constants/status.js`，按 `docs/specs/domain-model.md` §2.3：缴费取药与看报告合并为第 9 步，`HOME` 显示「已完成」。
5. 演示会话 `mock/session.js` 在 `session.hello` 后先回 `ready` 再推当前节点首轮，避免首屏空白；`sos` 与文字含「找不到」触发升级且不推进节点。
6. 设计令牌 `--scale` 三档（1 / 1.15 / 1.3），用户端用浅色底、金色主操作，与设备端 `device/src/style.css` 同一套色值。
7. 新增 `docs/adr/ADR-020` 与 `docs/specs/mini-program.md`，写明「预览可以、上架不做」，不改变基线 §3.3。
8. `manifest.json` 的 `appid` 保持 `touristappid`（测试号），`pages.json` 四个页面统一自定义导航栏。
9. 端口固定 5173，与 `device/src/member-pages.js` 的默认地址一致，设备端 iframe 可直接加载。
10. 页头 `AppHeader.vue` 改成「返回在左、标题居中、状态在右」；小程序端用 `uni.getMenuButtonBoundingClientRect()` 取胶囊真实位置，动态给右侧留白，避免返回按钮被微信胶囊覆盖。取不到胶囊信息时按 `statusBarHeight + 6` 兜底，不退化为 0。
11. 精简结构：删掉无引用的 `fetchHealth`、`ACCESSIBILITY_LABELS`、5 个未使用 getter、`ElderButton` 的 `disabled`/`loading` 两个未传过的 prop，以及本地 `.gitignore` 里与根目录重复的 4 行。
12. `src/api/` 原本建了没人调用，改为在进度页真实使用：`DEMO_MODE=0` 时调 `fetchEpisode()`，失败回退本地样例并提示，使该目录不是空壳。
13. 微信开发者工具生成的 `project.config.json` / `project.private.config.json` 含真实 AppID，已加入 `.gitignore`，不进仓库。

## 已知风险与留待后续

- 小程序只用开发者工具构建验证，**未在真机与体验版走查**；正式环境需 HTTPS/WSS 与合法域名；
- 页面 UI 目前只有纯函数测试，没有组件测试与 Playwright E2E，留到 T6 的 L3 层；
- 登录、短信验证码、家属端页面未实现，按 `docs/specs/access-control.md` 留到 W3；
- 语音采集与 TTS 未接入，`mic` 暂用文字输入代替；
- 演示会话是脚本，不是状态机；真实状态机在服务端（ADR-003），W3 接 Django 后删除 `mock/session.js` 的演示职责；
- 小程序上架仍属基线 §3.3 明确不做项，本 PR 不改变该结论；
- 微信开发者工具会锁住 `dist/build/mp-weixin`，导致构建写不进目录、工具里看到的仍是旧包。开发时改用 `npm run dev:mp-weixin`（产物在 `dist/dev/mp-weixin`）可避免该问题。
