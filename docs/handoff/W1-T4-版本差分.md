## 一句话说清它干什么

读两个版本的本体快照，输出「新增 / 删除 / 修改 / 编号漂移」四类结果：`--format json` 给 T3 页面接，`--format text` 给人读。

## 数据流

两个 `ontology_<版本>.jsonl` → 按 schema §4.1 的主键 `triple_id` 各建一个字典 → 求差得分「只新版有 / 只旧版有 / 两边都有」→ 「只新版有」的再拿业务键 `(head_id, rel, tail_id)` 回旧版对账，能对上且旧编号已消失的记「编号漂移」，不算增删 → 「两边都有」的逐字段比对判定是否算「改」→ 拼成 `counts / added / removed / modified / id_drift / identity / compared_fields` → 按 `--format` 渲染。全程只读文件。

## 我改了什么（人工修改点）

1. 判等键按 schema §4.1 用主键 `triple_id`；业务键降级为对账，避免重建库时把 17 条知识报成 17 删 17 加（§8 第 3 条把业务键定为判重键，此推断才有依据）。
2. 编号漂移单独进 `id_drift`，不计入 `counts`；换号且改内容时两条记录都出，两个事实都不隐瞒。
3. 比对字段补 `head_id / rel / tail_id`，同一个编号下换头或换尾不再漏报；`comparable_fields()` 只比两侧快照实有的列，报告末尾声明未比对项。
4. 录入校验：缺 `triple_id` 报文件与行号、编号重复直接报 `DiffVersionInvalid`，不静默丢行。
5. `to_record()` 作为对外字段名唯一出口，按 §4.2 输出 `head/tail` 嵌套与 `provenance.anchor_id`，拿不到的 `type / label / standard` 不输出、不臆造。
6. 不 import `store.diff_versions()`，不修改 `store.py`（T2 的内核，只读）。
