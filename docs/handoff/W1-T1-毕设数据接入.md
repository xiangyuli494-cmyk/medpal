## 一句话说清它干什么

把毕设里的检查项、科室、排班数据搬进新仓库，并给旧系统留一条只读、可降级的调用通道。

## 数据流

离线路径：medical.sql（49MB dump）→ tools/legacy/extract_seed.py 解析 INSERT 语句 → 按白名单取三张表 → 去重、脱敏医生姓名 → fixtures/legacy/*.json → 检查规划引擎读文件。

在线路径：业务代码 → LegacyClient.find_location → GET 8001/ai/mixed/find_location/ → 成功则返回房间列表；超时或非 JSON 则抛 LegacyUnavailable → 调用方读 fixtures。

## 我改了什么（人工修改点）

1. 解析器自己写：dump 里 INSERT 是单条巨型语句，不能按行读，改成状态机解析，处理转义引号与 NULL。
2. 加了表白名单，只认三张表；user / registration / chat / checkpoints 直接不读，避免误把患者数据带进来。
3. 医生姓名做了哈希脱敏（医生-<sha1 前 4 位>），同一人前后一致，但不可还原。
4. 检查项名称去掉尾部下划线（源数据里带），并把 rs / fybz 从字符串转成整数。
5. 适配器只重试网络错误，不重试业务错误；非 JSON 抛 LegacyContractError 而不是当成网络问题重试。
6. 按旧代码改正了接口形态：原来是 POST 不是 GET，body 是 check_query，返回带 code；非 200 直接判不可用，不做重试。
7. 房间字段同时接受 room / location / wzsm 三种写法，因为旧检索层返回的键名还没定。

- 旧库 49MB 的 dump 里仍可能混有个别 PII 字段，W2 由 T6 抽查一次导出的 JSON；
- 旧系统的密钥轮换还没做，属 W1 遗留项。
