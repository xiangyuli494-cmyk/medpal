## 一句话说清它干什么

让任何人一条命令就能证明 ASR/TTS/OCR/Push 四类能力的接口契约没被改坏，不必等接上真实供应商。

## 数据流

测试进程 → `asyncio.run()` 驱动 `backend/adapters/fakes.py` 的假实现 → 假实现按 `backend/adapters/base.py` 的 Protocol 返回 `AsrResult` / `OcrResult` / `bytes` / `bool` → 断言字段、置信度、调用计数与错误类型继承关系。全程不联网、不读密钥、不写磁盘。

~~~mermaid
flowchart LR
  A[pytest] --> B[test_adapters.py]
  B -->|asyncio.run| C[FakeAsr / FailingAsr]
  B -->|asyncio.run| D[FakeTts / FakeOcr / FakePush]
  C --> E[AsrResult text + confidence]
  D --> F[OcrResult fields + confidence]
  E --> G[断言：文本非空 / 置信度阈值 / 调用计数]
  F --> G
  G --> H[AdapterError 四个子类继承检查]
~~~

## 我改了什么（人工修改点）

1. 新增 `backend/tests/test_adapters.py`，12 条用例：8 条正向 + 4 条参数化，覆盖 `FakeAsr`（返回文本、调用计数、构造参数生效）、`FailingAsr`（置信度 < 0.6 必须走求证）、`FakeOcr`（剂量字段低置信、字段与置信度集合对齐）、`FakeTts`（返回字节流）、`FakePush`（调用留痕）以及 `UpstreamTimeout`/`QuotaExceeded`/`EmptyResult`/`LowConfidence` 四个错误类型统一继承 `AdapterError`。
2. 调整 import 顺序：首版把 `FailingAsr` 写在 `FakeAsr` 之后，ruff 报 I001，按字母序（F-a-i < F-a-k）改为 `FailingAsr, FakeAsr, FakeOcr, FakePush, FakeTts`。
3. 刻意不用 `pytest.mark.asyncio`：`requirements-dev.txt` 里没有 `pytest-asyncio`，改用 `asyncio.run()` 驱动异步接口，做到零新增依赖；动依赖文件属于 T6 的范围，不在本 PR 顺手改。
4. 断言写「行为」不写「实现」：例如置信度用阈值 `>= 0.8` / `< 0.6` 而不是硬编码 0.92，改假实现的具体数值时用例不该跟着改。
5. **AI 参与度：部分使用。** 初稿由 AI 生成，人工改动为上述第 2、3、4 条。按 14 号 §6.1 A4，合并前还需另一名成员完成至少一处实质性修改，候选见文末「已知风险」。
