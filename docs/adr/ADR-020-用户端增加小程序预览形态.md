# ADR-020 用户端增加微信小程序预览形态

- 状态：已接受（W2）
- 日期：2026-10-27
- 决策人：T2（提出），T3（用户端负责人）会签，T1 知会
- 关系：落实 ADR-004「用户端采用 uni-app，编译为 H5 与微信小程序」中的**小程序编译目标**；不改变 `docs/plan/00-项目工期与范围基线.md` §3.3「微信小程序上架」仍属明确不做项。
- 影响范围：`frontend/user-app/`、`docs/specs/mini-program.md`、`.env.example`、`.github/workflows/ci.yml`、`device/src/member-pages.js`（5173 端口约定不变）

---

## 1 背景

`frontend/user-app/` 在 W1 只有一个 `.gitkeep`。基线把用户端定义为「uni-app（Vue 3），编译为 H5 与微信小程序」，但仓库里既没有 uni-app 工程，也没有小程序构建产物，评审时无法判断：

1. 同一套页面在小程序端是否真的能编译；
2. 小程序端的 `uni.request` / `uni.connectSocket` 与 H5 的差异会不会把协议层写死；
3. 设备端 iframe 指向的 5173 端口，未来有没有真实页面可加载。

同时，基线 §3.3 明确「小程序上架」不做（需企业主体与审核周期）。因此本期需要的不是「上架一个小程序」，而是**把小程序作为第二个编译目标纳入开发方向**，用开发者工具预览，主演示形态仍是 H5。

## 2 备选方案

| 方案 | 内容 | 判断 |
| --- | --- | --- |
| A | 只做 H5，小程序等 W4 再说 | 否决。ADR-004 已把小程序写进决策；越晚接入，`uni.*` API 与 H5 专用 API 的分叉越多，返工越贵 |
| B | **建 uni-app 工程，H5 与 mp-weixin 双目标同时可编译；小程序只做开发者工具预览，不上架** | **采纳** |
| C | 单独建一个原生小程序工程，与 H5 两套代码 | 否决。违反「多端复用」规范（`docs/plan/12` §2.4），同一交互实现两遍 |
| D | 直接申请企业主体、走小程序上架 | 否决。八周内拿不到主体与审核窗口，与基线 §3.3 冲突 |

## 3 决策

1. **`frontend/user-app/` 改为 uni-app（Vue 3 + Vite）工程**，一套源码同时产出：
   - H5：`npm run build:h5`，开发端口 **5173**（与 `device/src/member-pages.js` 的默认地址一致）；
   - 微信小程序：`npm run build:mp-weixin`，产物 `dist/build/mp-weixin`，用微信开发者工具导入预览。
2. **小程序只做预览，不做上架。** `manifest.json` 的 `appid` 保持 `touristappid`（测试号）；不提交审核、不配置正式域名。基线 §3.3 的排除项继续有效。
3. **H5 仍是主演示形态。** 答辩、设备端 iframe、Playwright E2E 都以 H5 为准；小程序用于证明「同一套代码能编译到第二端」，并在开发者工具里做人工走查。
4. **协议层与传输层分离。** `services/protocol.js` 只做消息构造与校验（纯函数，Node 可直接单测）；`services/transport.js` 才接触 `uni.connectSocket`。这样小程序与 H5 共用协议层，平台差异收敛在一个文件。
5. **演示模式默认开启。** `VITE_DEMO_MODE=1` 时使用 `mock/session.js` 的脚本会话，不连后端、不连数据库；这满足「本次不搭数据库」的约束，也让小程序在没有合法域名时仍能预览完整流程。
6. **不新增后端与数据库。** 用户端只消费 `docs/api/ws-protocol.md` v0.1 的消息形状；真实接口在 W3 由 Django 接管，本 ADR 不引入任何表结构或迁移。

## 4 依据

1. **ADR-004 已经选了这个方向。** 本 ADR 不是新选型，而是把既有决策落成一个可编译的工程，避免文档与仓库继续脱节。
2. **平台差异必须现在暴露。** 小程序没有 `localStorage`、WebSocket API 不同、合法域名受限；这些差异在页面写多之后再发现，改动面是现在的数倍。
3. **测试可以零依赖。** 协议、步序换算、字幕切段、文案红线都是纯函数，`node --test` 直接跑，不需要安装 533 个 npm 包，适合放进 CI。
4. **不碰数据库符合本期约束。** 演示会话与演示陪诊单都是自建样例，不落库、不采集真实患者信息。

## 5 影响与代价

| 项 | 影响 |
| --- | --- |
| 依赖体积 | `npm install` 约 533 个包；仅构建时需要，CI 单测不安装依赖 |
| 构建时间 | H5 与小程序各一次构建，均在 1 分钟内完成（本机实测） |
| 维护成本 | 新增一套前端工程与 39 条纯函数测试；页面逻辑仍由 T3 主责 |
| 文档口径 | 基线 §3.3 不改；新增 `docs/specs/mini-program.md` 说明「预览可以、上架不做」 |
| 风险 | 微信开发者工具需勾选「不校验合法域名」才能连 `http://127.0.0.1` 与 `ws://`；正式环境必须 HTTPS/WSS，属已知限制 |

## 6 八周工期下的影响

风险降低。用户端骨架在 W2 即可编译出两端产物，T3 后续只需往 `pages/` 里填页面，不需要再动工程结构。小程序上架仍不在范围内，不占用 W4 范围冻结后的任何工时。
