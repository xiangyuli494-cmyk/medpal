# ADR-018 设备端形态为手持借出式陪诊机

- 状态：已接受（W1）
- 日期：W1
- 决策人：T1（提出），T2、T4 会签
- 关系：收窄 ADR-017 的决策范围。ADR-017 中「触摸为主要交互面、否决 12 键方案、最小点击区 88×88px、禁止手势」四条继续有效；其形态段、Kiosk 口径与「无任何物理按键」的表述由本条替代。
- 影响范围：`README.md`、`docs/specs/device-ia.md`、`docs/api/ws-protocol.md`、`docs/plan/00-项目工期与范围基线.md`（C3/C4）、`docs/plan/11-技术方案与接口契约.md`（设备硬件条目）、`demo/`

---

## 1 背景

ADR-017 要回答的问题是交互面用触摸还是用按键。四个备选方案（12 个物理键、3 个物理键、3 键加软键盘、全触摸）争的都是按键数量与误触成本，没有一维是设备拿在手上还是固定在墙上。但 ADR-017 的决策段把形态一并写成了「10.1 寸竖屏触摸屏、Chromium Kiosk 全屏」，背景段写成「一台放在门诊大厅、由老人自己使用的陪诊终端」。形态不是这一条 ADR 表决出来的，是从场景描写里带出来的。README 第 5 行「一台放在门诊大厅的终端」是它的改写。

仓库此后保留了三处与固定机不相容的功能，都没有随形态一起改：

1. **八个 beacon 点位讲解。** `docs/specs/device-ia.md` §6 第 6 步写「走到点位（beacon 自动触发）」，点位表列 B-01 门诊大厅、B-02 挂号收费处、B-03 内科诊区、B-04 外科诊区、B-05 检验科采血窗口、B-06 放射科、B-07 门诊药房、B-08 无障碍卫生间。固定在门诊大厅的机器只能触发自己所在的那一个点位，B-02 至 B-08 永远到不了。
2. **院内有声导航。** `NAVIGATE` 节点的正文是走路路径（出门左转、坐无障碍电梯到 2 层、出电梯右转），念给正在走路的人听。固定机念完，人一离开就断了。
3. **离院即清。** `demo/device-prototype.html` 五处写「仅院内租借使用 · 离院收回」「本设备仅限院内使用，离院请归还服务台」，「本地缓存为空（已清空，符合「离院即清」要求）」把数据清除挂在归还这个动作上。要归还的东西，必然是借出去的。

三处功能是本项目区别于院内自助机的部分，也是方案里对外讲的主线。形态不改，这三条没有物理前提。

---

## 2 备选方案

| 方案 | 内容 | 判断 |
| --- | --- | --- |
| A | 门诊大厅固定 Kiosk，10.1 寸竖屏，老人在机器前完成全部操作 | 否决。点位讲解、院内导航、离院即清三条失去落点；问路发生在路上，不在机器前。另需机柜、布线、固定安装，八周内做不完 |
| B | **手持借出式，7 寸 1024×600 横屏，服务台借出、离院前归还** | **采纳** |
| C | 老人自备手机加网页，不发放设备 | 否决。目标用户就是不会用智能手机的人；无法管控终端，离线包、音量、求助键都不可控 |
| D | 陪诊师持机、老人跟随，一机一人 | 否决。一间门诊配几十名陪诊师，人力成本不在项目范围 |

---

## 3 决策

1. **形态**：手持借出式。7 寸 IPS 触摸屏，1024×600 横屏，主控树莓派 4B（4GB），3D 打印外壳带挂绳孔，读卡区在机身背面，整机约 380 克，单手持握。
2. **借还**：门诊服务台凭身份证借出，扫设备编号与患者绑定，屏幕显示「本机为 07 号，今日 14:32 借出」；离院前归还，归还动作触发本地数据清除，屏幕逐条列出已删除项。
3. **交互面**：触摸为主，沿用 ADR-017 的 `touch.event` 与 `primary_label` 下发口径；另设五个实体键——电源、音量－、音量＋、按住说话、一键求助。电源、音量－、音量＋ 三键纯本地，不进 `touch.event`，不上行，也不进入业务状态；按住说话上行 `audio.start` / `audio.end`；一键求助上行 `touch.event { target: "sos", action: "long_press" }`；返回与主菜单并入顶栏右侧两个屏内控件，仍为纯本地。
4. **ADR-017 的范围收窄**：保留其「触摸为主交互面」「否决 12 键方案」「最小点击区 88×88px」「禁止手势」四条；其形态段、Kiosk 口径与「无任何物理按键」的表述由本条替代。
5. **硬件仍是条件交付**：C3（震动模块）、C4（整机）的触发条件与 W6 到货判定不变；未到货时以浏览器演示，形态口径不因此回退。

---

## 4 依据

1. **三处功能只在随身时成立。** 点位讲解、院内导航、离院即清是差异化最强、也在方案里被反复引用的部分，它们的共同前提是设备跟着人走。
2. **讲解机的心智。** 老人不需要学界面，机器跟着走、到点就讲。这比要求老人回到机器前重新操作，少一次折返。
3. **成本。** 树莓派 4B 套件 1086.82 元，7 寸 1024×600 IPS 触摸屏 219 元，两项合计 1305.82 元；含外壳、存储卡、电源，单台物料在 1500 元上下。Kiosk 需要机柜、布线与固定安装，施工与成本都不在八周范围内。
4. **借还顺带解决两个管理问题。** 凭编号借还可盘点院内资产；归还是数据清除的触发点，比后台定时清理更容易向患者解释。
5. **五个实体键回应了 ADR-017 否决方案 B 的理由。** 当时否决「3 个键 + 语音」的理由是「语音识别失败时无兜底路径」。音量、按住说话、一键求助放在机身上，不看屏也能用；同时没有回到 12 键的开模、丝印与误触成本。

| 对象 | 内容 |
| --- | --- |
| `README.md` | 首段改为借出式；目录树的 `device/` 一行改为 7 寸 1024×600 横屏 |
| `docs/specs/device-ia.md` | 设备形态行改为手持借出式与五个实体键；八区纵向预算按 800px 高度排的，横屏 600px 需重算，见待办 |
| `docs/api/ws-protocol.md` | 设备形态描述改为 7 寸横屏；明确五个实体键不进 `touch.event` |
| `demo/device-prototype.html` | 已在标题与借出提示上保留「院内便携式」「仅院内租借使用」，与本源一致，不需改 |
| 条件交付 C3、C4 | 整机口径由 Kiosk 改为手持，触发条件与到货周不变 |

代价有两项，写进方案时要一并说明：

1. **横屏 1024×600 与现有骨架不兼容。** `device-ia.md` §2 的八区纵向预算（顶栏 48 + 标题 56 + 正文 260 + 陪伴条 56 + 选项 200 + 主操作 100 + 字幕 44 + 底栏 120）是按 800px 高度排的，横屏只有 600px，需要按新的宽高比重排一遍。这是 W2 的工作量，不在本次文档改动内。
2. **借还引入一次人工动作与一套盘点制度。** 服务台要多一个借出登记与归还核对的动作，院方运营侧需要有对应岗位承接。这是方案里必须写明的前提，不能默认自动完成。

## 6 八周工期下的影响

硬件不设里程碑挂点。W1 只改文档口径，代码一行不动；W2 起设备端按 1024×600 横屏做逐屏骨架，平板与笔记本浏览器仍是验收载体。C4 整机在 W6 到货判定，未到货则演示改用浏览器，验收口径不变。
