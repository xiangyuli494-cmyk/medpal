# 合并规则：怎么才能合进 main

> **机器查两遍，人点一次头。** 少一样，合并按钮就是灰的。
> 本页记录仓库 Settings → Branches 里的实际配置；谁改设置，必须在同一个 PR 里更新本页，否则文档和线上很快会各说各话。

---

## 一、要交的三样

| # | 交什么 | 在哪 |
| --- | --- | --- |
| 1 | 代码 | 自己的分支上，不在 main |
| 2 | 交接单 | docs/handoff/W{周}-T{工号}-{模块}.md，**和代码同一个 PR** |
| 3 | PR | 开向 main，按模板填，勾掉该勾的 |

---

## 二、五个绿灯

| # | 条件 | 谁判 | 不满足时显示 |
| --- | --- | --- | --- |
| 1 | 分支已推送、PR 已开向 main | GitHub | — |
| 2 | CI / lint-and-test 绿 | 机器 | Required status check "lint-and-test" is failing |
| 3 | Handoff / handoff 绿 | 机器 | Required status check "handoff" is failing |
| 4 | 至少 1 人 approve（不能是作者本人） | 人 | At least 1 approving review is required |
| 5 | 分支与 main 无冲突、且基于最新 main | GitHub | This branch is out of date |

第 5 条是 strict 模式：**main 一动，你的分支就得 rebase 一次**。代码没问题也可能被这一条拦下。

---

## 三、机器查什么

### 3.1 CI / lint-and-test（五项全过才绿）

| 检查 | 内容 |
| --- | --- |
| 代码规范 | ruff check .，规则集 E / F / I，行宽 100 |
| 领域层边界 | backend/domain/ 里禁止 import django、requests、openai、dashscope、sqlalchemy、pymysql |
| 异常吞没 | 全仓库禁止 except Exception: pass |
| 红线扫描 | tools/check_guard_words.py，词表 14 条，命中即红 |
| 单元测试 | pytest backend/tests，附覆盖率报告（门槛 W2 起设为 100%） |

### 3.2 Handoff / handoff（三项判定）

| 判定 | 规则 |
| --- | --- |
| 有没有交 | 本 PR 改了 backend/ frontend/ device/ tools/ .github/ 下的文件，或任何 .py .vue .js .ts .tsx .jsx .ps1，就必须有 docs/handoff/ 下的新增或修改 |
| 小节全不全 | 四个小节缺一个就红：一句话说清它干什么 / 数据流 / 我改了什么（人工修改点） / 怎么验证的 |
| 内容够不够 | 每节去掉空格后至少 20 字；写「已完成」不算 |
| 文件名 | 必须是 W数字-T数字-名字.md |

**不算代码、不需要交接单的文件**：Makefile、pyproject.toml、requirements*.txt、.gitignore、docs/ 下的纯文档。这是当前检查器的已知盲区，见第七节。

---

## 四、交接单四节怎么写

| 小节 | 写什么 | 不合格的样子 |
| --- | --- | --- |
| 一句话说清它干什么 | 一句话，≤40 字，写「让谁能做什么」 | 「完成了模块开发」 |
| 数据流 | 输入从哪来 → 经过哪几步 → 输出到哪去，配一张图 | 只贴架构图，没有本模块的输入输出 |
| 我改了什么 | AI 生成后你亲手改的地方，逐条列 | 写「无」，但代码明显没动过 |
| 怎么验证的 | 命令、测试名、截图或录屏 | 写「已测试」 |

生成：python tools/new_handoff.py --module 模块名 --owner T2 --week 1
自查：python tools/check_handoff.py

---

## 五、人要做的三件事

1. **找人 approve**：作者不能批自己。至少一个协作者点 Review → Approve。
2. **rebase 到最新 main**：git pull --rebase origin main，再 push。strict 模式下不做这一步合不了。
3. **用 Squash and merge**：仓库只开了这一种合并方式，一个 PR 在 main 上留一个提交。合完删分支。

**禁止直接 push main，禁止 force push。** 保护规则里管理员也受约束（enforce admins 已开）。

---

## 六、被拦了怎么查

| 症状 | 原因 | 怎么改 |
| --- | --- | --- |
| handoff 红，提示没交自述 | 改了代码没交交接单 | 补一份，和代码放同一个 PR |
| handoff 红，提示缺小节 | 四节没写全 | 标题拼错也算缺失，照模板抄 |
| handoff 红，提示内容太短 | 某节少于 20 字 | 补两句具体的 |
| lint-and-test 红 | ruff 或测试挂了 | 本地先跑 ruff check . 和 pytest |
| 按钮灰但两个检查都绿 | 没人 approve | 找队友 Approve |
| 按钮灰，提示 out of date | main 动了 | git pull --rebase origin main 再推 |
| 按钮灰，提示 has conflicts | 与 main 冲突 | 本地解决冲突后推 |

本地一次跑完全部检查：

~~~powershell
python tools/check_guard_words.py
python tools/check_handoff.py
python -m pytest backend/tests -q
ruff check .
~~~

---

## 七、分支保护现状（与 Settings 一致）

| 设置 | 值 |
| --- | --- |
| 保护分支 | main |
| 必须走 PR | 是 |
| 必过检查 | lint-and-test、handoff |
| strict（必须最新） | 是 |
| 批准人数 | 1（作者不可自批） |
| 管理员同样受限 | 是 |
| 允许 force push | 否 |
| 允许删除分支 | 否 |
| 必须解决对话 | 是 |
| 合并方式 | 仅 Squash |

**已知盲区**：Makefile、pyproject.toml、requirements*.txt、.gitignore 改了不触发交接单检查。要补的话改 tools/check_handoff.py 的 CODE_PREFIXES / CODE_SUFFIXES，并同步更新本页第三节。

---

## 八、改规则

1. 改分支保护设置 → 同一个 PR 里更新本页第七节；
2. 改检查逻辑（ci.yml、handoff.yml、两个脚本）→ 必须在交接单的「我改了什么」里写清为什么改；
3. 本页与 Settings 不一致时，**以 Settings 为准**，并尽快把本页改回来。
