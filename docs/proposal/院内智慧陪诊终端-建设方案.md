# 院内智慧陪诊终端 · 建设方案

> 呈：医院管理部门 / 门诊部 / 信息科
> 版本：v1.0　编制日期：2026-10
> 性质：院内试点建设方案（教学项目，不收费、不用于商业用途）

---

## 一、我们要解决的是哪一件事

医院里每天都有一批这样的患者：**能自己走，但走不明白。**

他们不识字或看不清字，不会用自助机，听不懂叫号，找不到检查科室，看完医生记不住医嘱，取完药不知道一天吃几次。他们通常有家属，但家属在上班、在外地，来不了。

现在的办法是三种，各有各的问题：

| 现有办法 | 问题 |
| --- | --- |
| 导医台问路 | 只能指路，管不了挂号、检查、取药、医嘱这一整条链；高峰期一个人答不过来 |
| 志愿者 / 护工陪走 | 人力有限，一个志愿者同一时间只能陪一个人；排班、培训、管理都是成本 |
| 家属请假陪同 | 一个家属请一天假，损失一天工资；家属不在本地的根本来不了 |

**我们不打算增加人手，而是把「陪着一个老人走完全程」这件事，做成一台放在门诊大厅的设备。**

---

## 二、方案一句话

**一台立在门诊大厅的终端，老人不用学、不用打字、不用手机，从进院到离院全程有人「陪着说话」。家属在手机上远程看见进度与医嘱。**

设备的形态是 **10.1 寸竖屏触摸屏一体机**，立式或壁挂，接院内 WiFi 与电源。界面上只有大字、大按钮和语音，**没有键盘、没有输入框、没有需要滑动的操作**。

它不做医疗判断，不给用药建议，不替代医生。它做的是四件事：

1. **告诉老人下一步去哪、做什么、等多久**
2. **把医生说的话原样记住，再慢慢讲一遍**
3. **在老人紧张、等待、找不到路的时候，先安抚，再办事**
4. **出问题时，第一时间叫到人**

## 三、老人实际会经历什么（九步）

下面九步是设备端的完整主流程。**其中只有三步需要老人主动点屏幕，其余都是设备主动播报。**

| 步 | 老人在做什么 | 设备在做什么 | 老人需要点几下 |
| --- | --- | --- | --- |
| 1 | 走到设备前 | 屏幕自动亮起，播报「您好，今天由我陪着您」 | 0 |
| 2 | 把身份证放在读卡区 | 建档，屏幕显示姓名、年龄、家属手机（已脱敏） | 1 |
| 3 | 说「我胸闷」 | 追问一句「大概多久了」「有没有出汗」，给出建议科室 | 0（说话即可） |
| 4 | 看一眼建议科室 | 播报「建议看心血管内科，2 层 A 区 208 诊室，预计等 15 分钟」 | 1（确认挂号） |
| 5 | 走到候诊区 | 播报取号码与当前叫到第几位，快叫到时主动提醒 | 0 |
| 6 | 路过内科诊区 | 到点自动讲解「这里是内科诊区，请在此候诊」 | 0 |
| 7 | 说「带我去心血管内科」 | 分五步讲怎么走：出门 → 无障碍电梯 → 出电梯左转 → 沿走廊 → 到分诊台 | 0 |
| 8 | 看完医生出来 | 把医嘱逐条念一遍：「氨氯地平片 5 毫克，每天一次，早上吃，共 14 天」 | 0 |
| 9 | 办完事，要还设备 | 屏幕显示「本地缓存已清空」，身份证、人脸、病历临时文件全部删除 | 1 |

**整个流程，老人一共只需要点 3 次屏幕。** 其余全部靠说话和听。

遇到任何一步不会，设备上有三个固定的兜底：

- 说「**我不懂**」→ 换一种更简单的说法，把当前这一步重讲一遍
- 说「**我找不到**」→ 重播当前这段路，并同时通知服务台
- 说「**我要找人**」→ 直接转服务台，会话不断

## 四、三端是什么关系

系统一共三个界面，但它们不是三个独立的产品：

```
                    ┌──────────────────────┐
                    │   院内智慧陪诊终端    │  ← 产品本体
                    │   （门诊大厅的设备）  │
                    └──────────┬───────────┘
                               │ 同一份就诊记录
                 ┌─────────────┴─────────────┐
                 ▼                           ▼
        ┌────────────────┐          ┌────────────────┐
        │   家属端 H5    │          │   用户端 H5    │
        │ 微信里打开即可 │          │ 会用手机会员用 │
        └────────────────┘          └────────────────┘
```

**设备是本体，两个手机端是它的远程延伸。**

- **家属端**：微信里收到推送，能看到今天到哪一步了、医生说了什么、药怎么吃、下次什么时候复查。**不提供实时定位**——这不是一个监控工具。老人可以随时在设备上撤回授权，撤回后家属端立刻看不见。
- **用户端**：给会使用手机的当事人（比如陪父母来的中年子女）用，功能与设备端一致，只是在自己手机上。

三个界面共用同一份数据，不会出现「设备上记了、手机上没同步」的情况。

## 五、设备长什么样、放在哪

### 5.1 硬件形态

| 项 | 规格 |
| --- | --- |
| 屏幕 | 10.1 寸竖屏触摸屏，分辨率 800×1280 |
| 机身 | 立式支架或壁挂，高度适配坐姿与站姿（屏幕中心距地 1.1–1.3 米） |
| 交互 | 全触摸 + 语音，**无物理按键**，无键盘，无扫码枪 |
| 外设 | 身份证读卡器、定向扬声器、麦克风阵列（3 米内可拾音） |
| 网络 | 院内 WiFi；断网时降级为离线演示模式，不中断当前会话 |
| 电源 | 常供电，断电恢复后 30 秒内自动回到待机屏 |

### 5.2 建议布点

按老人最容易迷路的位置排优先级：

| 优先级 | 位置 | 理由 |
| --- | --- | --- |
| P0 | 门诊大厅入口 | 第一站，建档、挂号、问路需求最集中 |
| P0 | 内科诊区候诊区 | 候诊时间最长，老人最容易焦虑 |
| P1 | 检验科 / 放射科楼层 | 检查项目多、科室分散，迷路率最高 |
| P1 | 门诊药房 | 取药与用药交代是老人最记不住的环节 |
| P2 | 无障碍卫生间附近 | 配合紧急求助使用 |

**试点建议先装 1 台**（门诊大厅），跑通后再按上表扩展。设备之间共享同一份院内数据，不需要各自维护。

### 5.3 点位讲解（自动触发）

设备通过院内定位信标（蓝牙 beacon）识别老人走到了哪里，到点自动讲解。**老人不需要做任何操作**，走过去就讲。

试点阶段的 8 个点位：

| 点位 | 编号 | 讲解内容（示例） |
| --- | --- | --- |
| 门诊大厅 | B-01 | 门诊大厅，是您就诊的第一站。这里可以挂号、缴费、取号，也可以向服务台工作人员求助。 |
| 挂号收费处 | B-02 | 挂号收费处，可以现场挂号、缴费和打印发票。窗口设有低位柜台，方便轮椅使用者。 |
| 内科诊区 | B-03 | 内科诊区，包含心血管内科、呼吸内科和消化内科诊室。请在候诊区就坐，听到叫号后再进入诊室。 |
| 外科诊区 | B-04 | 外科诊区，包含骨科和普通外科诊室。诊区入口处设有扶手，地面为防滑材质。 |
| 检验科采血窗口 | B-05 | 检验科采血窗口，抽血前请先取号，抽血后请按压针眼五分钟。 |
| 放射科 | B-06 | 放射科，做 CT 或拍片前请取下身上金属物品，检查室内有工作人员全程陪同。 |
| 门诊药房 | B-07 | 门诊药房，取药请出示取药单，药师会当面交代用法用量。 |
| 无障碍卫生间 | B-08 | 无障碍卫生间，门为推拉式，内部设有扶手和紧急呼叫拉绳。 |

讲解词由医院提供，我们负责录入。**改文案不需要改代码。**

## 六、医疗安全：这套系统绝不会做的事

这是方案里最需要医院确认的部分。我们把边界写死，并且写进代码里强制检查。

**我们的边界，与国家标准的边界完全一致。**《社会化陪同就医服务 基本要求》（GB/T 47801—2026，2026-11-01 实施）明确：陪同就医服务人员可以提供**诊疗向导、代替排队、领取药品、陪伴交流**等服务，但**不能**提供涉及**检查结果判读、医疗建议、代为选择或同意治疗方案**等服务。

| 国家标准允许的 | 本设备做的 |
| --- | --- |
| 诊疗向导 | 九步流程引导、科室与诊室指引、院内分步导航 |
| 代替排队 | 自助挂号、候诊盯号、缴费与取药指引 |
| 领取药品 | 取药窗口指引、用法用量原样复述 |
| 陪伴交流 | 情绪陪伴、点位讲解、家属远程可见 |

| 国家标准不允许的 | 本设备的处理 |
| --- | --- |
| 检查结果判读 | 只复述医生原话与报告上的原始数值，不做解读；老人追问「要不要紧」时回答「这个得问医生，我帮您记下来」 |
| 提供医疗建议 | 14 个禁用词强制拦截；不给用药建议、不判断病情轻重 |
| 代为选择或同意治疗方案 | 挂号、缴费等有后果的动作一律二次确认，由老人自己点；系统不替任何人做决定 |

### 6.1 三条红线

| 编号 | 约束 | 怎么保证 |
| --- | --- | --- |
| **R-1** | 医学相关表述必须以医生原话为来源，不得表述为系统判断 | 所有面向老人的文本走三级管线：固定模板 → 限槽位润色 → 红线词校验。校验不通过退回模板 |
| **R-2** | 识别不确定时必须当场标记并求证，不得推断；剂量字段尤其 | 识别置信度低于 0.8 的剂量，屏幕必须显式标出「这个数字我没认准，请对着药盒看一眼」，**不做自动纠错** |
| **R-3** | 重要医疗材料必须电子化留存，交接有留痕、可追溯 | 每次状态变化写一条时间轴记录，谁在什么时间做了什么可查 |

### 6.2 系统在任何情况下都不会说这些话

以下 14 个词 / 句式被列为禁用词，出现在任何面向老人的文本里都算缺陷，自动化测试会拦截：

```
没事的　不严重　不要紧　我认为　应该是　肯定是　你得的是
建议您吃　可以加量　加一片　不用去医院　小毛病　放心吧没事　我诊断
```

**目标是把出现次数做到 0，不是「尽量少」。** 这条写进了验收门槛。

### 6.3 哪些环节禁止使用 AI 生成

| 环节 | 是否允许 AI 生成 | 原因 |
| --- | --- | --- |
| 挂号二次确认 | **禁止** | 重要操作必须用固定脚本，防止确认语句被改写 |
| 医嘱复述 | **禁止** | 必须逐字取自医生原话，剂量绝不能被改写 |
| 药品名称、剂量 | **禁止** | 原样转录，任何生成都算缺陷 |
| 费用与医保金额 | **禁止** | 涉及金额，必须用模板与明细拆解 |
| 行程播报、报告通俗化 | 允许（限槽位） | 只能改措辞，不能新增医学事实，改完要过一致性校验 |
| 分诊科室建议 | 允许 | AI 只做「文本→科室」的映射，最终结论由确定性规则投票产生 |

### 6.4 免责声明必须挂载

| 场景 | 屏幕与语音上必须出现的话 |
| --- | --- |
| 涉及医学结论 | 「以上是医生原话，我不能替医生判断。」 |
| 涉及费用或医保 | 「最终以医院结算单为准。」 |
| 涉及分诊建议 | 「分诊仅作就诊参考，不能替代医生诊断。」 |

### 6.5 老人情绪异常与紧急情况

- **红旗指征拦截**：说到「胸痛 + 出汗 / 呼吸困难」或「嘴角歪 + 说话不清 + 一侧无力」时，系统**不允许继续走普通流程**，强制改推急诊科，并播报「请立即前往急诊科，或点右下角红色「一键求助」，我们会立刻通知服务台护送您」。
- **一键求助**：设备右下角常驻红色求助区，长按 1.5 秒（或 3 秒内点两次）触发。工单直达服务台，带上点位与老人信息。服务台确认派员后，设备上会显示「工作人员正在赶往」——**必须有人接手才算闭环**。
- **情绪陪伴**：识别到紧张、焦虑、独处、等待过久时，设备会先用短句慢速安抚，再办事情。这部分可以随时在设置里关闭。

## 七、数据与隐私

| 项 | 我们的做法 |
| --- | --- |
| 采集什么 | 就诊流程状态、语音（用于识别）、医嘱文本、检查与缴费凭证 |
| 不采集什么 | **不采集真实人脸模板**（演示阶段）、不采集身份证原图、不做实时定位 |
| 数据存多久 | 见《数据留存规范》：就诊记录按院内规定留存，到期自动删除并写删除日志 |
| 谁能看 | 老人本人；被授权的家属（且可随时撤回）；院内相关人员按岗位权限 |
| 撤回授权 | 老人本人在设备上撤回，家属端**立刻**不可见，不需要等审核 |
| 设备归还 | 一键清空本地缓存：身份证号、人脸模板、病历临时文件全部删除，屏幕明确告知已删除 |
| 设备鉴权 | 设备令牌只对一个就诊单有效，与就诊同生命周期，最长 4 小时；令牌不进 URL、不进日志 |

## 八、与医院现有系统的关系

**这一点需要医院明确：本期不做 HIS 接口对接。**

原因很实在：HIS 接口需要厂商配合与授权，排期不可控，八周内无法保证。所以我们采取的做法是：

| 数据 | 来源 |
| --- | --- |
| 科室、诊室位置、检查项目、院内方位 | 从院内公开资料与既有数据整理，形成本地字典 |
| 号源（哪天、哪个医生、还剩几个号） | **自建号源中心**，结构参照院内排班习惯（科室-医生-日期-时段-余号），扣减有事务保护，不会超卖 |
| 医嘱、报告 | 试点阶段由医护人员在后台录入或确认；正式接入 HIS 时替换为接口读取 |

**这意味着：**试点阶段这套设备是**旁路运行**的，不碰 HIS，不影响现有业务，出问题也不会影响医院正常运转。等到验证有效、医院愿意推进时，再把号源与医嘱换成 HIS 接口即可，前端与交互不用改。

这是我们认为对医院风险最小的推进方式。

## 九、无障碍：三类人群都要能用

| 通道 | 谁 | 怎么用 | 硬性要求 |
| --- | --- | --- | --- |
| 老人大字 | 视力尚可、识字不多 | 大字 + 语音 + 大按钮 | 正文不小于 24 号字；触摸区不小于 88×88 像素 |
| 视力障碍 | 全盲或重度弱视 | **全程语音，零点击** | 界面上不得存在「必须点击才能继续」的元素 |
| 听力障碍 | 听不见 | 文字优先 + 「替我说」把想说的话显示给医生看 | 系统旁白出声次数为零 |

触摸目标的尺寸标准是 88×88 像素，是国际无障碍规范（WCAG）要求的两倍——因为老人手抖、指腹大。所有可点区域之间的间距不小于 16 像素，防止误触。

**不使用任何手势**：不滑动、不双击、不双指缩放。唯一的长按是一键求助，而且有单击兜底。

## 十、实施计划

八周，六个角色，分四个里程碑。

| 里程碑 | 时间 | 交付什么 | 医院能看到什么 |
| --- | --- | --- | --- |
| **M1** | 第 2 周末 | 三端骨架可启动；领域层单元测试全覆盖 | 设备上能看到界面，能点，但流程还没通 |
| **M2** | 第 4 周末 | 九个步骤全流程走通（用模拟数据） | **可以现场演示完整一遍**，从进院到离院 |
| **M3** | 第 6 周末 | 真实语音识别、语音合成、单据识别接入 | 说话能被听懂，医嘱能念出来，单据能识别 |
| **M4** | 第 8 周末 | 真人可用性测试（≥ 10 位老人）、交付、答辩 | 有真实的测试报告与改进记录 |

### 需要医院配合的事项

| 事项 | 时间 | 说明 |
| --- | --- | --- |
| 明确一位对接人 | 第 1 周 | 用于确认讲解词、科室信息、布点位置 |
| 提供院内公开资料 | 第 1–2 周 | 科室分布、检查项目、楼层方位图 |
| 确认讲解词与话术 | 第 2–3 周 | 我们出初稿，医院审核定稿 |
| 允许现场观察 | 第 3–6 周 | 在门诊大厅观察老人实际使用（不采集个人信息） |
| 协调可用性测试 | 第 7 周 | 邀请 10 位左右老人试用（知情同意后） |
| 场地与网络 | 第 6 周前 | 1 个试点点位：电源、WiFi、摆放位置 |

## 十一、验收标准（可量化）

不是「感觉还行」，而是逐条打勾。

### 11.1 功能验收

| 项 | 标准 |
| --- | --- |
| 全流程走通 | 九个步骤无阻断，全程无需工作人员介入 |
| 老人独立完成率 | 10 位测试老人中，≥ 8 位能在无提示下完成建档与挂号 |

## 十三、这套方案不做什么

把边界说在前面，避免后续期望错位：

| 不做 | 原因 |
| --- | --- |
| 医院 HIS 系统接口对接 | 本期无授权与排期，改为旁路运行 + 自建号源中心 |
| 多院区 / 多医院覆盖 | 限定单一院区场景 |
| 医生、护士使用的界面 | 由医院现有 HIS 承担 |
| 材料交接签署 | 设备端只做「已交付」确认与留痕，不做签署 |
| 微信小程序上架 | 需企业主体与审核周期，改用 H5 |
| 实时定位家属 | 这不是监控工具，且涉及隐私 |
| 医疗诊断建议 | 系统不做任何医疗判断 |
| 端侧大模型 | 设备性能不允许，全部走院内服务端 |
