## 命名硬规则

1. **`episode` 不许写成 `visit` / `order` / `trip` / `case`。** 一个老人一次到院 = 一个 `episode`，不是一次就诊、不是一张订单。
2. **角色只有三个：`elder` 老人、`family` 家属、`staff` 院内人员。** 系统侧另有 `system`（系统）与 `dev`（开发）两个非人类角色。
3. **`task` 是待办任务，`timeline` 是时间轴，两者不可互换。** 时间轴记录「发生了什么」，任务记录「要做什么」。
4. 状态枚举一律 `UPPER_SNAKE`，与 `EpisodeStatus` 逐字一致，中文名只用于界面与文档。
5. 新术语先在本表登记标识符，再进代码。未登记的标识符不允许出现在 `backend/`、`frontend/`、`device/` 里。
6. **`device` 是设备端，是产品的本体。** 本项目交付的核心是一台放在门诊大厅的终端；`user_app` 与 `family` 是它的两个远程延伸，不是并列产品。

## 变更规则

- 追加术语：在本表末尾按分组编号追加，同时更新 `docs/specs/domain-model.md`（若是实体或字段）。
- 改标识符：等同破坏性变更，须同步改代码、协议与 mock，并升次版本号。
- 删术语：允许整条删除，删除须同步升版本号并在 ADR 中记录。
